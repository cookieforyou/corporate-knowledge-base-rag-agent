## 1. 系统构成与部署拓扑

```
ECS 单机（2C/8G，无 GPU）
├── PostgreSQL 18          【宿主机原生安装】——唯一事实源（文档/Chunk/审计/会话/反馈/词表规则）
├── 既有 Compose（存量，不在本平台编排内）
│   ├── Elasticsearch 9.4.2   ——BM25 检索（失败不阻断，经重建通道修复）
│   ├── Redis 8               ——会话记忆/限流账本/审批账本/重建任务表
│   ├── MinIO                 ——文档原件 + 备份副本（kb-backups bucket）
│   └── Milvus 2.6            ——向量库（默认 provider，可切 pgvector）
├── docker-compose.app.yml（本平台·应用面）
│   └── kb-api               ——Spring Boot 4.1 / Java 21，端口 8090
└── docker-compose.monitoring.yml（本平台·观测面）
    ├── Prometheus 2.55.1（告警规则 14 条）
    ├── Grafana 11.5.2（五面板）
    ├── Jaeger all-in-one 1.62.0（本地 trace 核验）
    └── node_exporter v1.9.1（Host 层指标）
外部：Langfuse Cloud 免费档（LLM trace，OTLP 出境，用户已知悉接受）
```

**连接口径（定案）**：分层 Compose 不纳管存量服务——应用/监控容器统一经 `host.docker.internal`（`extra_hosts: host-gateway`）连接宿主端口，兼容 PG 原生与存量 Compose 端口映射两形态。共享 external network 直连为可选优化。

**可用性口径**：单机现实目标 **99.5%**（99.9% 需多节点，不承诺）；灾备最小集 = PG 备份 + 恢复演练（ES/Milvus 可经重建通道再生）。

## 3. 环境变量（`infra/.env`）

从 `infra/.env.example` 复制后填写；键与 `application-infra.yml` / `application-ai.yml` 占位一一对应。核心族：

| 族 | 键 | 说明 |
|---|---|---|
| 镜像 | `KB_IMAGE_TAG` | **必填**（`:?` 守卫拒启），禁 latest |
| 数据库 | `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | PG 连接（容器内经 `host.docker.internal:5432`） |
| MinIO | `MINIO_ENDPOINT` / 凭据 | 文档原件 + 备份 |
| 向量库 | `KB_VECTOR_STORE_PROVIDER`（缺省 milvus）/ `KB_MILVUS_*` / `KB_PGVECTOR_*` | 双向量库切换 |
| Redis/ES | `REDIS_HOST` / `ES_URIS` 等 | `REDIS_DB` 必须 0（会话记忆） |
| 认证 | `JWT_ISSUER_URI` | Casdoor 签发地址 |
| LLM | `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` | 主模型 + 备用/Embedding/Rerank/Judge |
| 观测 | `TRACING_OTLP_ENABLED` / `LANGFUSE_OTLP_AUTH` / `TRACING_SAMPLING` | 缺省关导出零噪音 |
| 词表 | `RAG_GUARDRAIL_RULES_SOURCE`（file\|db）/ `RAG_GUARDRAIL_RULES_EXPORT_DIR` | 护栏词表源选择 |
| 备份 | `BACKUP_PG_*` / `BACKUP_MINIO_*` / `BACKUP_*` | 备份脚本专用（宿主侧地址，非 host.docker.internal） |
| 监控 | `GRAFANA_ADMIN_USER` / `GRAFANA_ADMIN_PASSWORD` | **必填**（`:?` 守卫） |
| 内存 | `KB_API_MEM_LIMIT`（缺省 3G） | 按 ECS 规格校准 |

## 4. 部署步骤

### 4.1 首次部署

```bash
# 0. 前置：PG/ES/Redis/MinIO/Milvus 已就绪（既有），mc 已安装（备份依赖）
cd /opt/kb-rag-agent

# 1. 构建镜像（宿主侧先出 fat jar——2 核不做镜像内 Maven 构建）
bash infra/scripts/build-image.sh          # 产出 tag 如 v1.0.0-a1b2c3d

# 2. 配置 Secrets
cp infra/.env.example infra/.env && chmod 600 infra/.env
vi infra/.env                              # KB_IMAGE_TAG / 各连接凭据

# 3. 启动应用（含 Flyway 自动迁移，见 §5）
cd infra && docker compose -f docker-compose.app.yml up -d
docker logs kb-api -f                      # 确认启动完成 + Flyway 段

# 4. 启动监控栈
docker compose -f docker-compose.monitoring.yml up -d

# 5. 开机自启
sudo systemctl enable --now kb-api kb-monitoring

# 6. 自检
curl -s localhost:8090/actuator/health     # {"status":"UP"}
```

### 4.2 Flyway 迁移版本化

- 机制：`baseline-on-migrate=true` + `baseline-version=0`——**非空现网库**首跑插 baseline 登记行，V1 脚本（十表幂等快照）零结构变更；**空库**直建。
- **新增 schema 变更纪律**：先写 `kb-domain/src/main/resources/db/migration/V(N+1)__*.sql`，再同步 `schema.sql` 全量快照（双源一致性单测守卫）；**禁止手工 ALTER**。
- 验证：`psql -d <db> -c "select version, description, success from flyway_schema_history"`。

### 4.3 升级发布

```bash
git pull && bash infra/scripts/build-image.sh        # 新 tag
# infra/.env 更新 KB_IMAGE_TAG 至新 tag
cd infra && docker compose -f docker-compose.app.yml up -d   # 滚动替换
docker logs kb-api -f | grep -iE "flyway|started"    # 迁移 + 启动确认
```

### 4.4 AppCDS 启动加速（可选）

```bash
cd infra
docker compose -f docker-compose.app.yml --profile tools run --rm kb-api-cds-train
# 训练服务完整启动后超时 SIGTERM 写档共享卷 kb-cds；重启生产容器即消费
docker compose -f docker-compose.app.yml up -d
```

`--enable-preview` 与 CDS 兼容性若实测失败，entrypoint 自动回落普通启动，零功能影响。

## 5. 日常运维

### 5.1 启停与自愈

```bash
cd infra
docker compose -f docker-compose.app.yml ps                 # STATUS healthy
docker compose -f docker-compose.app.yml restart kb-api     # 重启
docker compose -f docker-compose.app.yml logs -f kb-api     # 日志（轮转 50m×3）
sudo systemctl stop kb-api        # 整体停用（含监控另停 kb-monitoring）
```

自愈分层：进程崩溃/健康检查失败 → compose `restart: unless-stopped` 拉起；开机自启 → systemd oneshot。**职责不混用**。

### 5.2 健康检查面

| 端点 | 用途 | 鉴权 |
|---|---|---|
| `/actuator/health` | 存活/就绪（compose healthcheck 消费） | permitAll |
| `/actuator/info` | 版本信息 | permitAll |
| `/actuator/prometheus` | Prometheus 抓取 | permitAll |
| `/actuator/metrics/**` | 指标明细 | permitAll |

暴露面即以上四项（include 白名单钉死）；**网络层收敛经 ECS 安全组**（8090 收敛可信源、监控端口办公源、基础设施端口零公网——见用户侧清单 SG1）。

### 5.3 关键日志提取

```bash
docker logs kb-api 2>&1 | grep -E "热重载成功"          # 词表热重载（本地 + pub/sub 各一条为正常）
docker logs kb-api 2>&1 | grep -E "熔断|fallback"       # 主备切换
docker logs kb-api 2>&1 | grep -E "REJECTED|429"        # 护栏/配额拒绝
```

## 6. 备份与恢复（灾备最小集）

> 边界论证：PG 唯一事实源；ES/Milvus 经重建通道再生（§7.3）。故 **PG 备份 + 演练 = 最小充分集**。

### 6.1 定期备份

```bash
# cron 接线（每日 03:07，错峰）
echo "7 3 * * * /opt/kb-rag-agent/infra/scripts/pg-backup.sh >/dev/null 2>&1" | crontab -

# 手工首跑验证
bash infra/scripts/pg-backup.sh
ls -la $BACKUP_LOCAL_DIR            # 本地产物（保留 7 天）
mc ls minio/kb-backups/             # MinIO 远端副本（--md5 校验过）
```

产物：`pg_dump -Fc` 双副本（本地 + MinIO `kb-backups`）；flock 防重入；脚本自写 backup.log。

### 6.2 恢复演练（建议每月 / schema 变更前）

```bash
bash infra/scripts/pg-restore-drill.sh              # 基本演练（独立 {db}_drill 库，不触生产）
bash infra/scripts/pg-restore-drill.sh --strict     # 全 MATCH 方通过（CI 口径）
bash infra/scripts/pg-restore-drill.sh --from-minio # 验远端副本可恢复
```

判定三态：**MATCH**（一致）/ **LAG**（演练<生产，备份后新增数据）/ **FAIL**（缺表或逆序）。演练库 `CREATE EXTENSION vector` 权限预案：非超户报错时以 postgres 超户补装（脚本给出命令）。

### 6.3 索引重建（ES/向量漂移修复）

经运维中心重建面板或 `POST /api/v1/admin/rebuild`（详见 API 文档）：PG 事实源全量重解析 + ES 孤儿清扫 + 异步重嵌入。漂移收敛判据 = 蓝绿 diff + ES 孤儿为零。

## 7. 可观测

### 7.1 栈构成

- **Prometheus**：抓 `host.docker.internal:8090/actuator/prometheus` + node_exporter；告警规则 14 条（`alert-rules-kb-rag.yml`）。
- **Grafana**：五面板——概览 / 检索 / LLM / 业务 / **supplier-sla**（熔断时序/接管速率/降级占比）；登录口令即 `.env` 所设。
- **Jaeger**：本地 trace 核验（OTLP），验证链合树形态。
- **Langfuse Cloud**：LLM 调用树（生产观测主平台，`TRACING_OTLP_ENABLED=true` 开启；采样 `TRACING_SAMPLING` 缺省全量，错误随采样天然覆盖）。

### 7.2 告警速查（14 条，阈值待基线校准）

| 组 | 规则 | 处置入口 |
|---|---|---|
| JVM/进程（4） | Heap 高 / 重启 / 进程消失类 | §5.1 自愈核验，持续看 logs |
| LLM 特有（7） | 拒答率 / 反馈比 / 空检索率 / Token 突增 / 供应商错误率 / rerank 降级率 / 配额命中率 | 对应面板定位；供应商错误率 → §8.2 熔断 |
| Host（2） | 磁盘 / 内存 | 清理或扩容评估 |
| SLA（1） | KbPrimaryModelDegraded（主模型持续熔断） | §8.2；核备用凭据 `DASHSCOPE_API_KEY` |

告警自检矩阵（14 条全覆盖 = 真触发演练 + promtool 合成单测）见 `infra/prometheus/alert-selfcheck/` 与用户侧清单 M1。

### 7.3 词表热重载（护栏运营）

写路径：运维中心第五 Tab（DB 单轨，`RAG_GUARDRAIL_RULES_SOURCE=db`）→ 保存即自动重载 + pub/sub 广播 + 编码 YAML 存档（`/rules` 卷，随写同步，人工 `git commit` 归档）。回滚阀门：改回 `source=file` 重启。词表变更纪律见安全专项文档（新建默认 FLAG 观察，零误伤方转 BLOCK）。

## 8. 故障处置手册

| 症状 | 定位 | 处置 |
|---|---|---|
| healthcheck unhealthy | `docker logs kb-api` 尾部 | 查依赖连接（`.env` 凭据/宿主端口）；compose 自动重启中则等待收敛 |
| 回答持续走备用模型 | supplier-sla 面板 / `KbPrimaryModelDegraded` 告警 | 主模型凭据/额度核验；熔断器半开自动探测恢复，无需手工复位 |
| 检索结果异常/缺失 | 检索调试台（Debug 页）双路得分 | 单文档重解析（reparse）；全局漂移走重建（§6.3） |
| 限流/配额 429 频发 | `rag.guardrail.*` / 审计 REJECTED | 按租户调额（Redis 令牌桶/日预算配置族）；Redis 故障时配额 fail-open 不拒 |
| 审批功能不可用（写工具） | Redis 连通性 | 审批账本 **fail-closed**（Redis 恢复即自愈）——设计使然，非缺陷 |
| 上传 413 | 请求体/文件大小 | 单文件 50MB / 单请求 60MB 上限为设计值 |
| 流式对话中断 | 审计三态（ERROR 行）+ trace | Jaeger/Langfuse 查调用树断点；供应商超时走熔断接管 |
| ETL 卡在 PARSING | 文档状态列 + logs | FAILED 态可重试 reparse；处理期禁删为守卫语义（409） |

## 9. 安全运维要点

1. **镜像**：禁 latest（`:?` 守卫拒启）；tag = `v{semver}-{git短哈希}`。
2. **Secrets**：`infra/.env` 0600 不入 git；Grafana 口令 env 注入（明文 admin/admin 已终结）。
3. **安全组**：8090 收敛可信源；监控端口限办公源；PG/ES/Redis/MinIO/Milvus 端口零公网（SG1）。
4. **供应链**：dependency-check + CycloneDX 基线入档 `docs/reports/supply-chain/`（NVD API key 强制，无 key 扫描直接失败无回落）；治理项另立跟踪（B5）。
5. **CORS**：`APP_CORS_ALLOWED_ORIGINS` 白名单注入（默认仅 Vite dev 5173）；allowCredentials false。
6. **审计**：全链路审计恒开（`kb_audit_log`，三态）；MCP 通道轻量审计默认关（`rag.mcp.audit.enabled`）。

## 10. 例行自检（99.5% 兜底）

照 `docs/project-operations/99.5-兜底自检清单.md` 10 项执行（4.11 验收件）：

1. healthcheck 态 healthy　2. kill 容器自动拉起　3. reboot 自启（应用+监控）　4. Flyway history 在管　5. 备份 cron 在跑 + 双副本产物在　6. 恢复演练（建议 --strict）　7. 日志轮转生效　8. Prometheus targets 全 up　9. Grafana 面板有活数据　10. 告警通道自检（抽样）
