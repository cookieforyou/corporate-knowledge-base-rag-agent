## 1. 登录

1. 打开工作台地址，进入登录页。
2. 点击 **「Casdoor 登录」**——跳转企业统一身份认证（OAuth2/PKCE 流程）。
3. 在 Casdoor 页面完成登录后自动跳回工作台，会话令牌自动保存，无需重复登录。

> 登录后你只能看到**自己租户**的知识库与数据（多租户严格隔离）。若提示「身份不完整」，联系管理员确认账号已分配租户。

## 3. 智能问答（对话页）

### 3.1 两种模式

输入框左上方切换：

- **知识问答（rag）**：提问企业知识库内容。回答以流式逐字输出，每个事实性陈述附 **`[ref-N]` 证据引用**。
- **企业工具（tool）**：办理企业事务（如员工查询、年假余额、请假申请）。读类事务自动执行；**写类事务弹出审批卡片**——提交后等待审批人在审批端点确认，批准后再次确认即执行（一次性消费，防重复）。

### 3.2 溯源与原文

- 回答完成后，消息下方展开**溯源面板**：「溯源 · N 条证据（双路检索）」，列出被引用的知识片段。
- 正文中的 `[ref-N]` 徽标**可点击**，弹出原文对话框查看该片段所属文档内容（支持「查看原文」定位）。

### 3.3 多轮对话与历史会话

- 同一会话内连续提问自动携带上下文（窗口 20 条）；支持指代追问（如「那专业版呢」）。
- 左侧**会话栏**可收起/展开：列出历史会话，点击可**恢复并续聊**（历史消息与溯源面板一并恢复）。

### 3.4 反馈

每条回答右下角：

- **👍 回答准确 / 👎 回答待改进**：可改评。
- 点踩后建议补充「期望回答」——它会进入运维中心的 Bad Case 闭环，成为改进知识库的标注素材。

### 3.5 对话内快速上传

输入区左侧附件按钮可直接上传文档（与文档管理同通道），上传后顶部实时显示 ETL 进度。

## 4. 文档管理（知识采编）

### 4.1 上传

1. 点击 **「上传知识文档」**。
2. 选择**解析路由**：
   - **自动决策**（推荐）——系统按文本密度自动选择；
   - **NATIVE**（Tika 原生，电子文档）/ **DEEP**（DocMind 大模型，复杂版式）/ **OCR**（扫描件视觉识别）。
3. 拖拽或点击选择文件。

**支持格式**：PDF · DOCX · **PPTX** · **XLSX** · Markdown · TXT · HTML（单文件 ≤ 50MB；旧版 .ppt/.xls/.doc 请先转存为新格式）。

上传后文档状态流转：`上传中 → 解析中 → 成功/失败`，进度实时显示；处理中的文档禁止删除。

### 4.2 文档列表操作

每行四个操作（按状态可用/置灰）：

| 操作 | 说明 |
|---|---|
| **Chunks** | 打开该文档的切片观测抽屉（内容/页码/tokens/类型） |
| **重解析** | 用 MinIO 原件重走解析管道（解析升级或单文档修复，成功/失败态可用） |
| **替换** | 上传新版本文件覆盖原件并重新入库（版本自动 +1） |
| **删除** | 三库级联删除（处理中禁止；重复删除不报错） |

## 5. 检索调试台

输入查询 → **「执行检索」**，透视检索全链路（面向调试，不产生对话记录）：

- **链路时延**：改写/双路召回/融合/重排各阶段耗时；
- **查询改写**：原始查询与多轮消解后查询对照；
- **候选得分矩阵**：每个候选 Chunk 的向量分 / BM25 分 / RRF 融合分 / 重排分，条形可视化；
- **降级状态**：单路故障/重排降级时明确标记（OK/降级）。

用途：排查「为什么这条知识没被召回」或「排序为何如此」。

## 6. Chunk 观测台

选择文档 → 列出该文档全部入库切片（内容、页码、tokens、类型、状态）。用途：入库质量抽检、定位某条检索结果的原始切片。

## 7. 运维中心（管理员）

五个 Tab，一条运营工作流：**看数 → 查日志 → 标注 → 回灌改进**。

### 7.1 统计仪表盘

知识库概览（文档总数/状态分布/切片总量/解析路由分布/入库趋势）+ Bad Case 队列计数（点踩总数/待标注数）。

### 7.2 Chunk 运维

- 按文档浏览切片，支持**编辑内容**（编辑后异步重嵌入，检索即生效）/ **软删**（检索不可见）/ **恢复**；
- **重建面板**：发起全量或指定目标的索引重建，轮询任务进度与失败明细（三库漂移的修复兜底）。

### 7.3 日志查询

审计日志多条件过滤（时间/用户/会话/反馈/状态），行详情抽屉展示完整链路：改写查询、回答、重排序列、双路命中、工具调用。

### 7.4 Bad Case 处置

1. 从日志/点踩队列中找到问题问答；
2. **根因标注**（四分类）：检索未命中 / 改写漂移 / 生成幻觉 / 解析不足；
3. **一键回灌**：将该条转为评估用例（可快填期望答案与检索快照）写入 Golden Set——提交后随 CI 复跑防回归；
4. 反馈标记「已解决」闭环。

### 7.5 护栏词表

注入拦截词项的可视化运营：

- 查看词条活视图（分注入侧/输出侧、族系、动作）与**命中演练**（验证词条是否命中）；
- 新增/编辑/停用/删除词条（新建默认 **FLAG 观察**——只计数不拦截，验证零误伤后方可升级为 BLOCK 拦截，界面会警示）；
- 保存即热重载生效，无需重启；词表存档随写同步导出，人工提交 Git 即完成归档。

## 8. 常见问题

| 问题 | 处理 |
|---|---|
| 回答没有引用来源 | 可能是知识问被判为闲聊或证据为空被规范拒答——换个问法，或经检索调试台确认知识是否入库 |
| 上传失败 413 | 单文件超 50MB；压缩或拆分 |
| 上传失败「不支持的文件类型」 | 仅支持 §4.1 白名单格式；旧版 Office 格式请转存 |
| 写工具一直「等待审批」 | 审批未通过或已过期（审批有效期 10 分钟），重新发起 |
| 提示限流/预算不足（429） | 租户限流或日 Token 预算耗尽，稍后再试或联系管理员调额 |
| 删除文档/编辑切片被拒（处理中） | 等待该文档处理完成（状态变为成功/失败）后再操作 |
