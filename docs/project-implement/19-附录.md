## 附录 D：避坑指南与反模式

| # | 反模式 | 问题 | 正确做法 |
|---|--------|------|---------|
| 1 | 在 Controller 中直接 `new ChatClient()` | 无法复用 Advisor 链，配置散落 | 通过 `@Configuration` Bean 统一组装 |
| 2 | 在业务代码中拼接 Prompt | 难以维护、无法做 A/B 测试 | 使用 `PromptTemplateManager` 外部化管理 |
| 3 | 硬编码 API Key | 安全风险 | 使用 K8s Secrets / Vault / 环境变量 |
| 4 | 同步阻塞调用 OCR/LLM | Web 线程耗尽 | 使用 `@Async` + 虚拟线程异步处理 |
| 5 | 在 `synchronized` 块中调用虚拟线程 I/O | 虚拟线程 Pinning 退化 | 确保底层客户端无 synchronized 阻塞 |
| 6 | 不限次数的工具调用循环 | Token 消耗失控 | 设置 `ToolCallingAdvisor` 最大调用次数 |
| 7 | 检索结果全量注入 Prompt | Context Window 溢出 | 计算 Token 数，超限时压缩或减少 Top-K |
| 8 | Advisor 顺序随意编排 | 审计不完整、限流被绕过 | 严格按 Order 设计排列 |
| 9 | 不做检索结果评估 | Prompt 变更导致召回率下降 | CI 中集成 Golden Dataset 自动评估 |
| 10 | Milvus 连接不调优 | 高并发下连接耗尽 | 配置连接池参数，设置合理的超时时间 |
| 11 | SSE 代理无超时配置 | 长连接被网关切断 | 配置心跳保活 + `proxy_read_timeout` 延长 |
| 12 | 向量库替代所有检索 | 专有名词命中率低 | 混合检索（向量 + BM25）是必经之路 |
| 13 | 信任模型输出直接执行写操作 | 模型幻觉导致数据污染 | 写操作通过 approvalId 三段式 HITL 机制要求人工确认（第十一章 11.2.1） |
| 14 | 流式响应中工具调用未处理异常 | 前端 UI 卡死或状态混乱 | SSE 推送专用 ERROR 事件 + 前端 `onError` 优雅降级 |
| 15 | 结构化输出不做 `@Valid` 校验 | 字段缺失/类型错误未被发现 | 对 `.entity()` 输出施加 Bean Validation 约束 |
| 16 | 工具定义 Schema 膨胀导致上下文溢出 | Agent 携带大量工具时 Context Window 不够 | 使用 `ToolSearchToolCallingAdvisor` 按需检索工具，只注入相关 Schema |
| 17 | 向量库选型不考虑数据规模 | 千万级以内用专用库造成运维负担 | 千万级 Chunk 以下优先 PGVector，降低架构复杂度；上亿级选 Milvus |
| 18 | 测试环境调用真实 LLM | 测试不稳定、成本高、速度慢 | 单元测试和 CI 中使用 `@Primary` Mock ChatModel，E2E 才调用真实 API |
| 19 | 上下文压缩机制缺失 | 长文档场景检索后直接注入全量内容导致溢出 | 使用轻量模型或 `TokenTextSplitter` 先压缩证据再注入 Prompt |
| 20 | 多模型路由缺少熔断保护 | 故障模型反复重试拖垮整体服务 | 在 `SmartRoutingChatModel` 中集成熔断器，连续失败后自动隔离降级 |
| 21 | 手搓 ExecutorService+Future 并行检索管道 | 重复造轮子、容错/超时各写一遍 | Spring AI 2.0 模块化 RAG：`RetrievalAugmentationAdvisor` + 自定义 `DocumentRetriever`/`DocumentJoiner`，并发由框架 taskExecutor 调度 |
| 22 | 把设计文档示例代码当作可编译代码 | v1 文档含多处虚构 API（ChatClientRequest.from、ToolContext.requestApproval 等） | 以 Spring AI 2.0.0 GA Javadoc/源码为准，示例代码落地前先核验 API 存在性 |
| 23 | 用 Milvus 原生 BM25 承载中文专有名词检索 | Milvus jieba 实现有已知质量问题（milvus-io/milvus#36743），查询 DSL 与高亮能力弱 | 中文 BM25 走 Elasticsearch ik；Milvus 专职向量检索（v2 决策，2026-07 源码+文档核验） |

| ㉝ | **Redisson 4.6.1 `hasIndex` 与 Redis Stack 错误文案不兼容**——经 Lua 包裹 `FT.INFO` 判索引存在，仅错误文案匹配 "not found"/"no such index" 判不存在，否则原样上抛；Redis Stack / RediSearch 对不存在索引返回 "Unknown index name" → 惰性建索引永不执行（簇③语义缓存，服务侧补认 unknown index 文案族为不存在，11 §11.9） |
| ㉞ | **`@ConfigurationProperties` 类须有 Bean 注册**——仅注解无 `@Component`/`@EnableConfigurationProperties` 时条件装配启用态构造注入失败启动即崩；单测手工装配不覆盖启动期装配核验（簇③语义缓存，`SemanticCacheProperties` 补 `@Component` 对齐 `ParsingProperties` 先例） |
| ㉟ | **RediSearch TAG 查询特殊字符须反斜杠转义**——TAG 表达式内 `,.<>{}[]"':;!@#$%^&*()-+=~` 具语法含义（`-` 为否定符），值含连字符（UUID 形态必然）不转义即「Syntax error at offset N near …」；存储侧原值不动，转义只作用查询解析；RediSearch 查询面仅参数化查询（PARAMS）天然语法安全，手写查询串一律经转义函数（簇③语义缓存 `escapeTagValue`，11 §11.9） |
| ㊱ | **Bolt 协议禁经 nginx `http` 块反代**——Bolt 是二进制 TCP 协议（握手魔数非 HTTP），L7 http 反代回 HTTP 错误页 → 驱动报「Server responded HTTP」；须经 **`stream` 块 L4 终结**（`listen <port> ssl` + 证书 → `proxy_pass 127.0.0.1:7687`，`proxy_timeout` 自默认 60s 放宽至 30m 级防掐空闲长连接）；且 443 已被 http 块占用（同端口不可双模块绑定）→ bolt 的 stream 监听须另择端口（本项目 `bolt+s://<域>:7687`）；浏览器侧走 HTTP 端点（7474 族）连通不代表 bolt 连通（协议不同路）（簇④ 用户侧 E2E 热修，17 §17.6） |
| ㊲ | **多构造器类须显式 `@Autowired` 定夺**——Spring 仅在唯一构造器（或唯一非私有公共构造器）时自动裁决；生产构造器 + 测试桩构造器并存时启动即「No default constructor found」，生产构造器显式 `@Autowired` 钉死（簇④ `EntityExtractor`，用户侧 E2E 首启暴露） |
| ㊳ | **CompletableFuture 轮询超时 ≠ 线程中断**——`get(timeout)` 的 TimeoutException 被 `catch (Exception)` 兜住后调 `Thread.currentThread().interrupt()` 双杀：① 任务线程后续每次等待调用立即惊醒 → 轮询热自旋（anyOf 对象 + InterruptedException 满栈痕高速分配，数分钟即挤爆堆——用户侧大文档回填 OutOfMemoryError 根因）；② 中断标志常驻 → 同线程一切可中断调用（Redisson 计数回写等）全线 InterruptedException（观测计数全灭）。TimeoutException 只表示轮询窗口未走完；唯 InterruptedException 方恢复标志并上抛收敛（簇④ `GraphBackfillService`，用户侧 E2E 回填实证） |
| ㊴ | **Neo4j bolt+s 长闲置池化连接被中间层掐断**——驱动池化连接长闲置后被中间层闲置超时（云侧 NAT/会话跟踪疑因——实测 ~5 分钟即断，短于显式放宽的 nginx `proxy_timeout` 30m）掐断，首笔事务撞死连接 `beginTransaction` 瞬抛 `ServiceUnavailableException`（驱动指数退避重试自愈但留 WARN 噪声 + 首笔延迟）。治本 = `Config.withConnectionLivenessCheckTimeout`（闲置超阈值连接出借前验证存活，死连接剔除换新）——中间盒超时面不可穷举，不逐个枚举超时，应用侧钉探测（簇④ `Neo4jConfig`，驱动 6.1.0 API javap 实证；用户侧 E2E 三轮回填实证） |
