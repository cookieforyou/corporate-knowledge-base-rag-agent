  name: kb-api

  replicas: 3

    matchLabels:
      app: kb-api
  template:
    metadata:
      labels:
        app: kb-api
    spec:
      containers:
      - name: kb-api
        image: registry.example.com/kb-rag-agent:latest

          requests:

          httpGet:
            path: /actuator/health

          httpGet:
            path: /actuator/health/liveness
            port: 8080

  name: kb-api-hpa

  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70

## 17.4 容器化与应用编排（v2.55 新增，Phase 4 簇⑥ 4.11）

> 现状定案（用户 2026-08-20 确认）：ECS 基础设施 = **PG 宿主机原生安装** + ES/Redis/MinIO/Milvus 既有 Docker Compose 部署。应用面容器化采**分层 compose 不纳管存量**——存量服务全经宿主地址连接（容器内 `host.docker.internal`，compose `extra_hosts: host-gateway`），统一兼容 PG 原生与既有 compose 宿主端口映射两形态；共享 external network 直连为可选优化，探测存量网络后另议。

**资产清单（仓库版本化）**：

| 资产 | 路径 | 要点 |
|---|---|---|
| 应用 Dockerfile | 根 `Dockerfile` | eclipse-temurin 21 JRE + 宿主侧构建的 fat jar（2 核 ECS 不做镜像内 Maven 构建）+ curl（HEALTHCHECK 依赖）；`--enable-preview` 入口钉死 |
| 容器入口 | 根 `docker-entrypoint.sh` | AppCDS 动态消费——`/opt/cds/app.jsa` 存在挂 `-XX:SharedArchiveFile`，缺失回落普通启动（CDS 为加速优化非功能依赖）；`JAVA_OPTS` 调优注入位 |
| 应用编排 | `infra/docker-compose.app.yml` | kb-api：restart unless-stopped + healthcheck（/actuator/health）+ json-file 日志轮转（50m×3）+ 内存限额 env 可调（`KB_API_MEM_LIMIT` 缺省 3G）+ 词表存档卷 /rules；**镜像版本化纪律 `KB_IMAGE_TAG:?` 禁 latest**；`kb-api-cds-train`（profiles: tools）AppCDS 训练服务 |
| Secrets | `infra/.env.example`（模板入 git）/ `infra/.env`（实体不入 git，0600） | 全连接凭据 + 特性开关环境变量族（对照 application-infra/ai.yml 占位逐一收编）；主机名约定 host.docker.internal |
| 开机自启 | `infra/kb-api.service` | systemd oneshot + RemainAfterExit——职责分层：进程级自愈归 compose restart + healthcheck，systemd 只管开机自启与一键起停 |
| 构建脚本 | `infra/scripts/build-image.sh` | mvn package（skipTests）+ docker build；tag 缺省 `v{semver}-{git短哈希}` |

**AppCDS 落地形态（N5 定案）**：零代码改动、部署侧训练——compose `--profile tools run kb-api-cds-train`：完整启动（infra 须可达）+ `-XX:ArchiveClassesAtExit` + 超时 SIGTERM 退出即写档共享卷 `kb-cds`，生产服务重启后消费。**待 ECS 实测两项**：① `--enable-preview` 与 CDS archive 兼容性（训练跑失败即回落，零功能影响）；② 启动加速读数。GraalVM Native/CRaC 否决依据见 Phase 4 复审方案 N5。

**部署形态**：`bash infra/scripts/build-image.sh` → 填 `infra/.env`（KB_IMAGE_TAG 等）→ `docker compose -f infra/docker-compose.app.yml up -d`（监控栈文件随批2 生产化后合并 `-f` 同起）→ `systemctl enable --now kb-api` 开机自启。E2E 步骤见 `docs/project-progress/用户侧待执行项清单.md`。

## 17.5 灾备最小集（v2.57 新增，Phase 4 簇⑥ 批3）

> **最小集边界论证**：PG 是唯一事实源——Chunk/审计/会话/反馈/词表规则全量在 PG；ES 索引与 Milvus 向量可经重建通道再生（簇③ ReindexGateway：PG 全量重解析 + ES 孤儿清扫 + 异步重嵌入）；MinIO 原件 OSS 冷备为可选项未排期。故 **PG 定期备份 + 恢复演练即灾备最小充分集**，对齐第 8 章 4.11「灾备最小集」与 v2.29「单机 99.5% + 灾备兜底」口径。**簇④ 扩面（v2.66）**：图谱数据（第二台 ECS Neo4j Community）可经回填任务再生但需重付抽取费用（逐 chunk LLM 调用），dump 备份为成本兜底纳入灾备面——图数据是**增强件**：丢失不损事实源完整性（图路降级空路，双路检索不受影响）。

**资产清单**：

| 资产 | 路径 | 要点 |
|---|---|---|
| 定期备份 | `infra/scripts/pg-backup.sh` | 宿主侧执行（PG 原生安装）：`pg_dump -Fc` → 本地 `BACKUP_LOCAL_DIR` → mc 上传 MinIO `kb-backups` bucket（`--md5` 校验 + 远端 stat 复核）→ 本地仅保留 `BACKUP_LOCAL_RETAIN_DAYS`（缺省 7）天。flock 单实例锁防 cron 与手工重入；自写 backup.log 超千行截尾；cron 每日 03:07（错峰整点） |
| 恢复演练 | `infra/scripts/pg-restore-drill.sh` | 恢复至独立演练库 `{db}_drill`（不触生产）→ 表集比对 + 逐表行数比对。判定：MATCH（一致）/ LAG（演练<生产，备份后新增，非严格容忍）/ FAIL（逆序或缺表）；`--strict` 全 MATCH 方通过（安静系统 E2E 口径）；`--from-minio` 从 MinIO 拉最新对象（验远端副本可恢复）；`--api-check` 附 GET /api/v1/stats/overview 抽检 |
| 兜底自检 | `docs/project-operations/99.5-兜底自检清单.md` | 10 项：healthcheck 态 / kill 自动拉起（应用 + 监控栈抽检）/ reboot 自启 / Flyway 在管 / 备份 cron 与双副本产物 / 恢复演练 strict / 日志轮转 / targets 全 up——4.11 验收件 |
| 配置段 | `infra/.env.example` 备份段 | `BACKUP_PG_*`（宿主侧地址，非 host.docker.internal）+ `BACKUP_MINIO_*` + `BACKUP_BUCKET/LOCAL_DIR/RETAIN_DAYS/PG_EXTENSIONS`；DB 与 MinIO 凭据复用既有键不重复落 |
| 图谱备份（簇④） | `infra/scripts/neo4j-backup.sh` | 第二台 ECS 宿主侧执行：停服 → `neo4j-admin database dump` → 本地 → mc 上传 MinIO `kb-backups` bucket（`--md5` 校验）→ 启服 → 本地保留策略同 PG。systemd（`BACKUP_NEO4J_SERVICE`）/ docker（`BACKUP_NEO4J_CONTAINER`）双形态；cron 每日 03:37（与 PG 错峰）；**停备窗口秒级**——窗口内图路降级空路（降级矩阵 10.2 兜底），RAG 主链不受影响。Community 版无在线备份（企业版权限），停备为官方支持形态 |

**实证口径（落码核验）**：① `infra/.env` 含未引号多词值（`JAVA_OPTS=-Xms1g -Xmx2g`），bash `source` 即报错——脚本一律 **逐项 grep 解析**（`env_key`），docker compose 消费不受影响；② 转储含 `CREATE EXTENSION IF NOT EXISTS vector`——演练库已装时空操作短路，未装且非超级用户则 pg_restore 报权限错，脚本预装失败告警并给出 postgres 补装命令（演练步骤见用户侧清单 DR1）；③ `psql -c` SQL 错误缺省退出码 0——演练脚本比对查询钉 `-v ON_ERROR_STOP=1`。

**运维形态**：备份 cron 接线 `7 3 * * * /opt/kb-rag-agent/infra/scripts/pg-backup.sh >/dev/null 2>&1`（脚本内部自写日志）；恢复演练建议每月一次或 schema 变更前执行；mc（MinIO Client）为宿主侧依赖，安装命令见脚本头注。E2E 步骤见用户侧清单 DR1 + 99.5% 兜底自检清单。

## 17.6 Neo4j 图谱部署形态（v2.66 新增，Phase 5 簇④ 批3）

> **基建定案**（复审方案 §五 簇④ 实现提示）：Neo4j Community（GPLv3，内部部署
> 合规，分发场景另议）部署于**新购第二台 ECS 独占**（2C8G；与业务全家桶同机会
> 争资源——内存基线 4G+；企业级知识图谱 <100 万节点为极轻负载）。堆参数显式
> 钉死（heap ≈4G + page cache ≈2G）。

| 面 | 形态 |
|---|---|
| 连接配置 | `application-infra.yml` `spring.neo4j.*`（uri/username/password/database/超时/`liveness-check-seconds`），环境变量 `NEO4J_URI/NEO4J_USERNAME/NEO4J_PASSWORD`（`.env.example` NEO4J_* 键族）；生产形态 `NEO4J_URI=bolt+s://<域>:7687` |
| 网络接入（用户侧 E2E 实证） | Bolt 经 nginx **`stream` 块 L4 反代**（`listen 7687 ssl` TLS 终结 → `proxy_pass 127.0.0.1:7687`，`proxy_timeout` 30m 级防掐空闲长连接，安全组放行 7687）——**禁经 `http` 块 L7 反代**（二进制协议回 HTTP 错误页，驱动报「Server responded HTTP」，坑位㊱）；443 已被业务 https 占用 → bolt stream 另择端口；凭据不经明文 `bolt://`（保持 `bolt+s`）；浏览器 HTTP 端点连通不代表 bolt 连通（协议不同路） |
| 驱动装配 | 原生 `neo4j-java-driver`（Boot 4.1 BOM 托管 6.1.0）手工装配 `Driver` Bean（`Neo4jConfig`，`destroyMethod=close`）——不引 spring-boot-neo4j starter，连接生命周期完全受 `rag.graph.enabled` 门控（关闭态无 Driver、无连接尝试、无 health 副作用）；**闲置连接存活探测**（v2.79）：`withConnectionLivenessCheckTimeout`（缺省 60s）——池内连接闲置超阈值出借前验证存活，死连接剔除换新（坑位㊴：三轮实证长闲置连接被中间层掐断，中间盒超时面不可穷举——实测 ~5 分钟即断，短于 nginx `proxy_timeout` 30m，云侧 NAT/会话闲置超时疑因——故应用侧钉探测而非逐个枚举超时） |
| Schema 初始化 | 启动期幂等 DDL（`GraphSchemaInitializer` @ ApplicationReady：约束 ×2 / 租户复合索引 ×2 / 1024 维余弦向量索引），失败不阻断启动（图路运行期单路容错兜底） |
| 故障语义 | 图谱是检索增强件非事实源：Neo4j 不可达 → 图路降级空路（双路检索不受影响）；启动期初始化失败 → 错误日志显形 + 运行期同降级 |
| 备份 | `neo4j-backup.sh`（17.5 资产清单，停备窗口 + dump → 本地 + MinIO 双副本） |
| 运维端点 | `POST/GET /api/v1/admin/graph/backfill`（存量回填，单租户单任务 409 守卫，10.9.5） |
| 验收 | 多跳准确率 >80% + 抽取抽检 >85% + 三路融合 P95 <600ms + `rag.graph.enabled=false` 零回归（10.9.6 / 18 章联动） |
