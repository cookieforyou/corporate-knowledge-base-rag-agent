## 17.1 Kubernetes 生产部署（关键配置）

```yaml
# kb-api-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: kb-api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: kb-api
  template:
    metadata:
      labels:
        app: kb-api
    spec:
      containers:
      - name: kb-api
        image: registry.example.com/kb-rag-agent:latest
        resources:
          requests:
            memory: "2Gi"
            cpu: "1000m"
          limits:
            memory: "4Gi"
            cpu: "2000m"
        env:
        - name: JAVA_OPTS
          value: "-Xmx3g -XX:+UseZGC -XX:+ZGenerational"
        - name: SPRING_PROFILES_ACTIVE
          value: "production"
        readinessProbe:
          httpGet:
            path: /actuator/health
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 10
        livenessProbe:
          httpGet:
            path: /actuator/health/liveness
            port: 8080
          initialDelaySeconds: 60
          periodSeconds: 30
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: kb-api-hpa
spec:
  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
```

## 17.3 平台层安全配置（v2.44 新增，安全簇② B1-B5 落档）

> 17.1/17.2 为 K8s/Milvus 集群设计目标形态（v2.29 复审已否决，现阶段 ECS 单体部署）；本节记录**实际部署形态**的平台层安全配置事实，设计细节见第十二章 §12.9。

| 面 | 配置事实 | 落点 |
|---|---|---|
| CORS | 白名单 `app.cors.allowed-origins`（env `APP_CORS_ALLOWED_ORIGINS`，默认 Vite dev 5173）；allowCredentials false、方法/头收敛 | kb-api application.yml + SecurityConfig |
| 上传上限 | multipart 单文件 50MB / 单请求 60MB + DocumentService 同值复核；超限 413 | kb-api application.yml + GlobalExceptionHandler |
| chat 请求体 | `app.chat.max-body-size` 默认 1MB，Content-Length 先行拦截 413（chunked 不拦，登记留观察） | ChatBodyLimitFilter |
| 安全响应头 | CSP `default-src 'none'` + frameOptions DENY + HSTS（一年含子域）显式钉死，默认头保持 | SecurityConfig.headers() |
| actuator 暴露面 | include 白名单四项（health/info/metrics/prometheus）即钉死；permitAll 维持供采集；**网络层源址限制（ECS 安全组）随 Phase 4 簇⑥生产加固落地** | kb-api application.yml |
| MCP 通道配额 | 只读工具独立桶 `rag:ratelimit:mcp:{tenant}` 120 次/60s fail-open；审计日志恒开、DB 轻行 `rag.mcp.audit.enabled` 默认关 | application-ai.yml + kb-ai-agent mcp 包 |
| 供应链基线 | dependency-check 13.0.0 + CycloneDX 2.9.3（不绑生命周期）；**NVD API key 强制**（13.x 实证），SBOM 首跑 + 漏洞扫描 2026-08-18 基线入档 docs/reports/supply-chain/（84 项 CRITICAL 11/HIGH 31/MEDIUM 40/LOW 2，治理另立跟踪） | 根 pom.xml |

## 17.4 容器化与应用编排（v2.55 新增，Phase 4 簇⑥ 4.11）

> 现状定案（用户 2026-08-20 确认）：ECS 基础设施 = **PG 宿主机原生安装** + ES/Redis/MinIO/Milvus 既有 Docker Compose 部署。应用面容器化采**分层 compose 不纳管存量**——存量服务全经宿主地址连接（容器内 `host.docker.internal`，compose `extra_hosts: host-gateway`），统一兼容 PG 原生与既有 compose 宿主端口映射两形态；共享 external network 直连为可选优化，探测存量网络后另议。

**资产清单（仓库版本化）**：

| 资产 | 路径 | 要点 |
|---|---|---|
| 应用 Dockerfile | 根 `Dockerfile` | eclipse-temurin 21 JRE + 宿主侧构建的 fat jar（2 核 ECS 不做镜像内 Maven 构建）+ curl（HEALTHCHECK 依赖）；`--enable-preview` 入口钉死 |
| 容器入口 | 根 `docker-entrypoint.sh` | AppCDS 动态消费——`/opt/cds/app.jsa` 存在挂 `-XX:SharedArchiveFile`，缺失回落普通启动（CDS 为加速优化非功能依赖）；`JAVA_OPTS` 调优注入位 |
| 应用编排 | `infra/docker-compose.app.yml` | kb-api：restart unless-stopped + healthcheck（/actuator/health）+ json-file 日志轮转（50m×3）+ 内存限额 env 可调（`KB_API_MEM_LIMIT` 缺省 3G）+ 词表存档卷 /rules；**镜像版本化纪律 `KB_IMAGE_TAG:?` 禁 latest**；`kb-api-cds-train`（profiles: tools）AppCDS 训练服务 |
| Secrets | `infra/.env.example`（模板入 git）/ `infra/.env`（实体不入 git，0600） | 全连接凭据 + 特性开关环境变量族（对照 application-infra/ai.yml 占位逐一收编）；主机名约定 host.docker.internal |
| 开机自启 | `infra/kb-api.service` | systemd oneshot + RemainAfterExit——职责分层：进程级自愈归 compose restart + healthcheck，systemd 只管开机自启与一键起停 |
| 构建脚本 | `infra/scripts/build-image.sh` | mvn package（skipTests）+ docker build；tag 缺省 `v{semver}-{git短哈希}` |

**AppCDS 落地形态（N5 定案）**：零代码改动、部署侧训练——compose `--profile tools run kb-api-cds-train`：完整启动（infra 须可达）+ `-XX:ArchiveClassesAtExit` + 超时 SIGTERM 退出即写档共享卷 `kb-cds`，生产服务重启后消费。**待 ECS 实测两项**：① `--enable-preview` 与 CDS archive 兼容性（训练跑失败即回落，零功能影响）；② 启动加速读数。GraalVM Native/CRaC 否决依据见 Phase 4 复审方案 N5。

**部署形态**：`bash infra/scripts/build-image.sh` → 填 `infra/.env`（KB_IMAGE_TAG 等）→ `docker compose -f infra/docker-compose.app.yml up -d`（监控栈文件随批2 生产化后合并 `-f` 同起）→ `systemctl enable --now kb-api` 开机自启。E2E 步骤见 `docs/project-progress/用户侧待执行项清单.md`。
