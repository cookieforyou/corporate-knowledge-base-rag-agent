### 5.2 Advisor 拦截器链完整设计

本项目规划 **10 个 Advisor**，构成完整的请求处理管道（v2 Order 重排：先审计、再鉴权、后限流/预算——未鉴权请求不消耗租户限流配额，审计覆盖被拒请求；与第十一章 11.2 表同源）：

| Order | Advisor | 接口 | 职责 | 阶段 |
|-------|---------|------|------|------|
| **10** | `AuditTraceAdvisor` | `BaseAdvisor` (before+after) | 全链路审计日志落库（最外层，含被拒/被限流请求） | P2 |
| **20** | `AuthAdvisor` | `BaseAdvisor` (before) | JWT 鉴权，提取用户/租户信息入上下文 | P2 |
| **30** | `TokenBudgetAdvisor` | `BaseAdvisor` (before+after) | Token 消耗统计、成本追踪、预算告警 | P2 |
| **100** | `RateLimitAdvisor` | `BaseAdvisor` (before) | Redisson 令牌桶限流，用户/IP/租户级（远期可迁 Higress AI Gateway） | P2 |
| **110** | `OutputGuardrailAdvisor` | `BaseAdvisor` (after) | 输出合规审查、竞品过滤（升级路线见 12.2.1） | P2 |
| **300** | `InputSanitizeAdvisor` | `BaseAdvisor` (before) | PII 脱敏、Prompt 注入检测（先于记忆，避免 PII 落库） | P2 |
| **400** | `MessageChatMemoryAdvisor` | `BaseAdvisor` | 多轮对话记忆（Redis 仓储），历史上下文注入 | P2 |
| **450** | `RetrievalTraceAdvisor` ★ | `BaseAdvisor` (before+after) | 请求级检索上下文填充（tenant/ACL）+ 溯源旁路透传 | **P1** |
| **500** | `RetrievalAugmentationAdvisor` ★（内置 `HybridDocumentRetriever` 双路召回） | `BaseAdvisor` | **核心**：查询改写+双路检索+RRF融合+重排+证据注入 | **P1** |
| **1000** | `ToolCallingAdvisor` | `CallAdvisor` | 工具调用循环，@Tool + MCP 工具编排 | P2 |

### 5.3 Java 21 虚拟线程应用策略

| 应用场景 | 并发模型 | 收益 |
|---------|---------|------|
| 混合检索（向量+BM25） | `StructuredTaskScope.ShutdownOnFailure` | 双路并行，总延迟 = max(向量, BM25) |
| 文档 ETL 管道 | `@Async` + 虚拟线程 | 异步非阻塞，Web 线程立即返回 |
| SSE 流式推送 | `Flux` + 虚拟线程 | 非阻塞 I/O，支持高并发连接 |
| OCR API 调用 | 虚拟线程 HTTP 客户端 | 避免线程池耗尽 |
| 批量向量化 | `parallelStream()` + 虚拟线程 | CPU 密集型任务并行加速 |

**关键注意事项**：确保底层 HTTP 客户端（RestClient/WebClient）支持虚拟线程，避免 synchronized 块从而导致 Pinning。
