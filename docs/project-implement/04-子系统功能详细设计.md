### 4.1 知识采编子系统

**核心流程（2026-10 落地形态）**：

```
上传（七格式白名单）→ MinIO 原件 → SmartParsingRouter（NATIVE / DEEP / OCR）
  → HtmlProtectingSplitter（保护 table/img + heading_path + 确定性 chunk ID）
  → SanitizingTransformer（PII/S4 入库消毒，打标不阻断）
  → PG kb_chunk（事实源）→ 向量化（10 条/批）→ 向量库 + ES 双写
  → ETL COMPLETED 终态帧：语义缓存失效 + 图谱抽取异步派发（可选）
```

**详细功能点（✅ 已交付 / 🟡 收窄 / ⬜ 未实施）**：

| 功能 | 描述 | 技术实现 | 优先级 | 状态 |
|------|------|---------|--------|------|
| 多格式上传 | PDF/Docx/PPTX/XLSX/MD/TXT/HTML；ContentType 白名单唯一拦截面 | Spring MVC MultipartFile | P0 | ✅ |
| 文本密度探测 | 扫描件识别 | PDFBox 文本提取 + 启发式 | P1 | ✅ |
| Tika 原生解析 | 电子文档直接提取 | `TikaDocumentReader` | P0 | ✅ |
| 解析智能路由 | 扫描件/复杂表格走深度链路 | `SmartParsingRouter`（NATIVE/DEEP/OCR；失败回落） | P1 | ✅ |
| HTML 结构保护 | `<table>`/`<img>` 保护 + 递归 DOM + 围栏/行内 code/结构标签配平 | `HtmlProtectingSplitter`（9.2 v2.22-v2.30） | P1 | ✅ |
| Token 切分与元数据 | heading_path、page_num、chunk_type、确定性 chunk ID | 自定义 Transformer | P0 | ✅ |
| 异步 ETL | 虚拟线程异步 + WebSocket 进度 | `DocumentEtlService` + `/ws` | P1 | ✅ |
| 表格/图片 Chunk | TABLE/IMAGE 独立 chunk（原 HTML 保真） | `chunk_type = TABLE / IMAGE` | P1 | ✅ |
| 增量重入库 | reparse/replace + version + REINDEXING 占用 + 蓝绿 CLEANUP | `DocumentService` + `ChunkCleanupService` | P2 | ✅ |
| 上下文增强 | 文档级语境前缀（默认开，A/B 定案） | `ContextualEnrichmentTransformer`（并发 8） | P2 | ✅ |
| 批量导入 | ZIP 包 + 目录结构 | — | P2 | ⬜ 未实施 |

> **落地边界**：上传入口唯一收敛于文档管理页（对话窗上传已移除）；ETL 异步完成前文档不可检索；增量重入库窗口检索不中断、失败重试幂等收敛。

### 4.2 智能检索子系统

**核心流程（三路 + 缓存 + 间接注入扫描）**：

```
用户 Query
  → QueryRoutingAdvisor(440) 意图分类/改写预写（闲聊旁路）
  → CacheCheckAdvisor(460) 语义缓存命中？→ 命中重放（带溯源）
  → RetrievalGateAdvisor(500) 门控
       → CompressionQueryTransformer（历史感知改写）
       → HybridDocumentRetriever 并行三路（向量 / BM25 / Graph，单路 5s 降级）
       → RrfFusion（K=60，N 路泛化）
       → RerankDocumentPostProcessor（qwen3.7-text-rerank，故障降级截断）
       → 间接注入扫描（warn/exclude）
       → ContextualQueryAugmenter（[ref-N] 编号化 + 空证据拒答）
  → 主答生成 → SSE TRACE 三路得分
```

**详细功能点**：

| 功能 | 描述 | 技术实现 | 优先级 | 状态 |
|------|------|---------|--------|------|
| 向量检索 | 语义相似度召回 | Milvus / pgvector（租户+软删过滤） | P0 | ✅ |
| BM25 检索 | 中文关键词召回 | Elasticsearch ik | P1 | ✅ |
| Graph 检索 | 实体匹配 → 1 跳展开 → chunk 反查（零 LLM） | `GraphDocumentRetriever`（`rag.graph.enabled` 门控） | P3 | ✅ |
| 多路并行 | 三路虚拟线程并行 + 单路超时降级 | `HybridDocumentRetriever` | P1 | ✅ |
| RRF 融合 | N 路泛化 Reciprocal Rank Fusion | `RrfFusion`（K=60） | P1 | ✅ |
| 重排序 | Cross-Encoder 精排 | DashScope `qwen3.7-text-rerank` | P1 | ✅ |
| 查询改写 | 多轮指代消解（消费 history） | `CompressionQueryTransformer` | P2 | ✅ |
| 意图路由 | 闲聊/元问题免检索 | `QueryRoutingAdvisor`(440) + `RetrievalGateAdvisor`(500) | P2 | ✅ |
| 语义缓存 | 相似问命中短路 | Redis 8 RSearch KNN 0.95 + 文档 TAG 失效 | P3 | ✅（缺省关） |
| 多知识库路由 | 不同领域独立 VectorStore | — | P3 | 📁 归档（11 章 §11.4.1） |
| 检索参数自适应 | RL 优化 topK/阈值 | — | P3 | ⬜ 未实施 |

> **落地边界**：图路缺省关，关闭态双路逐字节不变；语义缓存缺省关，命中率随真实流量观察；调试台与 TRACE 均透传 vector/bm25/graph 三路得分。

### 4.3 Agent 对话子系统

**核心流程（三链路物理隔离）**：

```
POST /api/v1/chat[/stream]  body: {query, sessionId?, mode: rag|tool|agent, approvedToolCallId?}
  ├─ mode=rag   → ragAgentChatClient（kb-ai-core，纯检索零工具）
  │     Audit(10) → Budget(30) → Rate(100) → OutputGuarded(110) → Sanitize(300)
  │     → SemanticInjection(320) → Memory(400) → Routing(440) → Trace(450)
  │     → CacheCheck(460) → RetrievalGate(500，内包检索管线)
  ├─ mode=tool  → toolAgentChatClient（kb-ai-agent，纯工具零检索 + Mock 工具）
  │     共享安全/配额/记忆链 → ToolCallingAdvisor(1000) → HITL 写工具审批
  └─ mode=agent → orchestratorChatClient（kb-ai-agent，编排链，缺省关）
        共享链 + TaskBoundaryAdvisor(420) → ToolCallingAdvisor(1000)
        主 Agent 只持 task 委派工具 → 三子代理（检索/数据/撰写）
```

**详细功能点**：

| 功能 | 描述 | 技术实现 | 优先级 | 状态 |
|------|------|---------|--------|------|
| 基础对话 | 同步 + 流式 | `ChatClient.call()` / `.stream()` | P0 | ✅ |
| 模块化 RAG | 改写 + 三路 + RRF + 证据注入 | `RetrievalAugmentationAdvisor` | P1 | ✅ |
| 证据注入 | 编号化 [ref-N] + 空证据拒答 | `ContextualQueryAugmenter` + GROUNDING_PROMPT | P1 | ✅ |
| SSE 流式 | TOKEN/TRACE/TOOL_CALL/REPLACE/PROGRESS/DONE | `Flux<ServerSentEvent>` | P1 | ✅ |
| 多轮记忆 | Redis 窗口 20 + PG 归档 + 续聊回填 | `MessageChatMemoryAdvisor` + `RedisChatMemoryRepository` | P2 | ✅ |
| 工具调用 + HITL | Mock 读写工具；写工具三段式审批 | `ToolCallingAdvisor(1000)` + `ToolApprovalService` | P2 | ✅（Mock 契约） |
| Multi-Agent 编排 | Orchestrator-Workers，三子代理 | `orchestratorChatClient`（`rag.orchestrator.enabled`） | P3 | ✅（收窄，缺省关） |
| 多模型路由 | 主备熔断，非复杂度三级路由 | `SmartRoutingChatModel` + fallback | P2 | ✅（收窄） |
| MCP Server | 三工具对外供给 | `/mcp` Streamable HTTP | P3 | ✅ |
| A2A / 钉钉 | 外部 Agent / IM 通道 | `/a2a` + `.well-known`；钉钉 Stream | P3 | ✅（缺省关） |

> **落地边界**：三链共享模型/记忆/护栏/配额，但各自独立装配；agent 链关闭态 400 `ORCHESTRATOR_DISABLED`；真实 OA/ERP 工具为 future/01 触发项。

### 4.4 溯源与可解释性子系统

**溯源数据模型**：

```java
public record AgentResponse(
    String answer,                    // 最终回答文本
    List<SourceCitation> sources,     // 引用来源列表
    RetrievalDetail retrievalDetail,  // 检索详情
    TokenUsage tokenUsage             // Token 消耗
) {}

public record SourceCitation(
    String chunkId,       // Chunk 唯一标识
    String fileName,      // 来源文件名
    Integer pageNum,      // 页码
    String content,       // Chunk 原文片段
    Double vectorScore,   // 向量相似度得分
    Double bm25Score,     // BM25 得分
    Double graphScore,    // Graph 路得分（图路在场时）
    Double fusionScore,   // RRF 融合得分
    String chunkType      // TEXT / TABLE / IMAGE
) {}
```

**详细功能点**：

| 功能 | 描述 | 技术实现 | 优先级 | 状态 |
|------|------|---------|--------|------|
| 来源标注 | 回答中自动标注 [ref-N] | Grounding Prompt 约束生成 + `RetrievalTraceAdvisor` 溯源透传（第十一章 11.1.2） | P1 | ✅ |
| 溯源卡片 | 前端展示来源文件/页码/三路得分 | SSE TRACE 事件（final 序列）+ Vue3 卡片 | P1 | ✅ |
| 检索得分透明化 | 前端展示各路检索得分 | 检索调试台 API（vector/bm25/graph 维度） | P1 | ✅ |
| Chunk 原文回看 | 点击引用查看完整 Chunk 内容 | 复用 `GET /documents/{docId}/chunks`（租户隔离）+ TRACE 投影 `docId` 通道（v2.12） | P1 | ✅ |
| 会话历史回显 | 历史消息恢复溯源与工具/委派卡片 | `kb_message.citations` + `metadata.toolCalls` | P1 | ✅ |
| 检索详情日志 | 每次检索完整记录 | `kb_audit_log.retrieved_chunks(JSONB)` | P2 | ✅ |
| 答案溯源链 | 答案→Chunk→Document 完整链路 | 数据关联查询 | P2 | ✅ |
