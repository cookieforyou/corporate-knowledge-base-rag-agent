## 10.0 架构决策裁决记录（2026-07-31）

检索架构经历过一次源码级核验后的方案变更，记录如下：

### 候选方案

| 方案 | 形态 | 裁决 |
|---|---|---|
| 甲（v1 原设计） | ES BM25 + Milvus 向量，`ExecutorService` 手搓并行 + 自研 `HybridRetrievalService` | ❌ 组件形态正确，实现方式废弃（2024 代手搓） |
| 乙 | Milvus 2.6 原生混合检索单引擎（BM25 Function + dense + 内置 RRFRanker） | ❌ 双重否决（见下），12 个月后可重估 |
| **甲+（v2 采纳）** | **ES BM25 + Milvus/pgvector 向量，构建于 Spring AI 模块化 RAG 之上** | ✅ |

### 方案乙的否决依据（源码级核验）

**框架层**（核验对象：`spring-projects/spring-ai` v2.0.0 tag 源码）：

1. `MilvusVectorStore` 的 schema 锁死为 4 字段（id/content/metadata/`FloatVector`），**无 sparse vector 字段、无 `FunctionType.BM25` 挂载点**，`initializeSchema=true` 建的正是这个 schema；
2. `doSimilaritySearch()` 是单路 dense `SearchParam`，**无 `HybridSearchReq`/`AnnSearchReq`/`RRFRanker` 的任何调用路径**，也无 builder 回调、protected 钩子等扩展点（类非 final 可子类化，但需重写 ~200 行核心方法）；
3. Spring AI 2.0 全仓**无 sparse embedding 抽象**（`Embedding` 类锁死 `float[]`），Milvus BM25 Function 需要的「text 字段 + 服务端分词」与 Spring AI 的 Document/Embedding 模型无法对接。

结论：走方案乙必须完全绕过 Spring AI 向量抽象自写 ~300 行 SDK 直连代码，失去 auto-config、观测集成与框架升级红利。

**引擎层**（核验对象：Milvus 2.5/2.6 官方文档 + GitHub Issues）：

4. Milvus 原生 BM25 虽已 GA 且吞吐基准优于 ES，但中文分词依赖内置 jieba，**存在已知质量问题**（milvus-io/milvus#36743：输出与原生 jieba 有显著差距），对"中文专有名词/标题词命中"这一本项目核心痛点是致命风险；默认 analyzer 对中文按字切分，必须显式配置；
5. 查询 DSL 能力缺口：无 aggregations、无完整 bool/phrase/fuzzy、高亮 2.6.8+ 才支持且不成熟——而这些能力恰好服务于运维后台（Chunk 查询、审计日志检索）与前端检索调试台。

**重估条件**（满足再议）：Milvus jieba 质量问题修复 + Spring AI 引入 sparse embedding 抽象或 MilvusVectorStore hybrid 支持。

### 方案甲+ 的论证

- **ES 存留的三重正当性**：ik 中文分词 10+ 年生产验证（核心痛点）；服务器已部署 ES 9.4.2（零新增运维）；高亮/复杂 DSL 未来服务 Chunk 观测台与审计查询；
- **框架惯用法替代手搓**：Spring AI 2.0 的 `spring-ai-rag` 模块提供完整模块化 RAG 抽象（`RetrievalAugmentationAdvisor` + `QueryTransformer`/`QueryExpander`/`DocumentRetriever`/`DocumentJoiner`/`QueryAugmenter`，均经源码核验存在），并发调度由框架 `taskExecutor` 承担，自研代码收敛为两个组件（ES retriever + RRF 融合）；
- **provider 无关性被扩展**：dense 路经 `VectorStore` 抽象，pgvector/Milvus 切换依然有效——混合检索在两个后端上都能工作（v1 设计反而将 BM25 硬绑定于 ES+Milvus 组合）；
- **检索调试台天然契合**：双路 retriever 各自产出得分与排名元数据，前端要求的"向量分/BM25 分/融合分"透明化是此结构的免费产物；Milvus 原生 hybrid 返回融合后难以拆解的分数，调试台反而难做。

**数据约定**（与第九章 ETL 对齐，全链路不变量）：

| 约定 | 值 |
|---|---|
| 融合键 | `chunk_id`（ETL 写入时 `Document.id = chunkId`，ES 文档 `_id`/`chunk_id` 同值） |
| 召回规模 | `recallSize = topK × 2`（`Constants.DEFAULT_TOP_K = 5`） |
| RRF 常数 | `Constants.RRF_K = 60` |
| 向量元数据键 | `chunk_id` / `doc_id` / `tenant_id` / `chunk_type` / `page_num`（ETL 写入） |
| 检索增补元数据 | `vector_score` / `bm25_score` / `vector_rank` / `bm25_rank` / `fusion_score` / `rerank_score` / `file_name` |
| 安全过滤 | `tenant_id` 等值 + `is_deleted=false` + 文档/部门级 ACL（Phase 3 扩展） |

## 10.2 HybridDocumentRetriever（双路并行 + 容错降级）

实现 Spring AI 的 `DocumentRetriever` 接口（`org.springframework.ai.rag.retrieval.search.DocumentRetriever`，签名 `List<Document> retrieve(Query query)`，经源码核验），作为 `RetrievalAugmentationAdvisor` 的单一 retriever 挂载点，内部编排双路召回与 RRF 融合。

```java
package com.enterprise.kb.ai.retriever;

import org.springframework.ai.document.Document;
import org.springframework.ai.rag.Query;
import org.springframework.ai.rag.retrieval.search.DocumentRetriever;
import org.springframework.ai.rag.retrieval.search.VectorStoreDocumentRetriever;
import org.springframework.stereotype.Component;

import java.util.List;
import java.util.concurrent.StructuredTaskScope;

/**
 * 混合检索器 —— 双路并行召回 + RRF 融合
 *
 * <p>作为 RetrievalAugmentationAdvisor 的 documentRetriever 挂载。
 * 双路各自容错：任一路失败/超时返回空列表并记录指标，两路结果交 RrfFusion 融合；
 * 两路全空时返回空列表，由 ContextualQueryAugmenter 的空证据路径兜底。</p>
 */
@Component
public class HybridDocumentRetriever implements DocumentRetriever {

    private final VectorStoreDocumentRetriever vectorRetriever;
    private final ElasticsearchDocumentRetriever esRetriever;
    private final RrfFusion rrfFusion;
    private final AiBusinessMetrics metrics;  // 见第十三章

    private static final int RECALL_MULTIPLIER = 2;

    public HybridDocumentRetriever(VectorStoreDocumentRetriever vectorRetriever,
                                   ElasticsearchDocumentRetriever esRetriever,
                                   RrfFusion rrfFusion,
                                   AiBusinessMetrics metrics) {
        this.vectorRetriever = vectorRetriever;
        this.esRetriever = esRetriever;
        this.rrfFusion = rrfFusion;
        this.metrics = metrics;
    }

    @Override
    public List<Document> retrieve(Query query) {
        long start = System.currentTimeMillis();
        int recallSize = Constants.DEFAULT_TOP_K * RECALL_MULTIPLIER;

        // 虚拟线程并行双路召回（Java 21 preview，父 POM 已启用 --enable-preview）
        // 注：VectorStoreDocumentRetriever 的 topK 只能在 builder 阶段固化（无实例级 withTopK），
        //     本 retriever 的 Bean 已按 topK = DEFAULT_TOP_K × 2 构建（见 10.6 装配）
        List<Document> vectorHits;
        List<Document> bm25Hits;
        try (var scope = StructuredTaskScope.open()) {
            var vectorTask = scope.fork(() -> retrieveSafely(
                () -> vectorRetriever.retrieve(query), "vector"));
            var bm25Task = scope.fork(() -> retrieveSafely(
                () -> esRetriever.retrieve(query, recallSize), "bm25"));
            scope.join();
            vectorHits = vectorTask.get();
            bm25Hits = bm25Task.get();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            return List.of();
        }

        List<Document> fused = rrfFusion.fuse(vectorHits, bm25Hits, recallSize);
        metrics.recordRetrieval(System.currentTimeMillis() - start,
            vectorHits.size(), bm25Hits.size(), fused.size());
        return fused;
    }

    /** 单路容错：失败/超时不拖垮整体，返回空并打点 */
    private List<Document> retrieveSafely(Supplier<List<Document>> call, String route) {
        try {
            return call.get();
        } catch (Exception e) {
            log.warn("检索路径 [{}] 失败，降级为空结果: {}", route, e.getMessage());
            metrics.recordRetrievalFailure(route);
            return List.of();
        }
    }
}
```

**降级矩阵**：

| 向量路 | BM25 路 | 行为 |
|---|---|---|
| ✅ | ✅ | 正常融合 |
| ✅ | ❌ | 仅向量结果（RRF 退化为单路排序，fusion_score = 1/(K+rank)） |
| ❌ | ✅ | 仅 BM25 结果（同上） |
| ❌ | ❌ | 空证据 → `ContextualQueryAugmenter` 空上下文路径，模型按 Grounding 规则回复"知识库中未找到相关信息" |

**`VectorStoreDocumentRetriever` 装配**（kb-ai-core 配置类）：

```java

        VectorStore vectorStore,
        ObjectProvider<RetrievalContext> retrievalContext) {
    return VectorStoreDocumentRetriever.builder()
```

### 10.2.1 请求级安全上下文 RetrievalContext

检索过滤器依赖请求级的 `tenant_id`（来自 JWT `owner` claim），而 `DocumentRetriever.retrieve(Query)` 签名不携带请求上下文。

> **v2.1 实现期修正（2026-08-02）**：v2 原设计为 `@Component @RequestScope` 作用域 Bean，由 RetrievalTraceAdvisor 在 Advisor 链入口从 SecurityContext 填充。**E2E 三轮实证否决**：MVC 异步请求（SSE 流式）在请求线程返回后即标记 `ServletRequestAttributes` 完结，CGLIB 作用域代理在**整个流式生命周期内不可解析**（`ScopeNotActiveException`，堆栈指认 reactor `loomBoundedElastic` 线程解引用失败）；且所有消费点被守卫静默降级——**租户过滤与 trace 记录在流式路径实际全部失效**（仅因测试租户恰好匹配而未显症状），SSE 尾帧崩溃只是最先显形的症状。ThreadLocal 传播（executor 装饰器重绑 RequestAttributes）亦无效：底层请求对象已完结，重绑后解引用仍失败。

**定稿方案：每请求纯实例 + Advisor 参数传递**（Spring AI 原生机制，源码核验：`RetrievalAugmentationAdvisor.before()` 以 `chatClientRequest.context()` 构建 `Query.context`）：

```java
/** 每请求纯实例——非 Bean，无作用域，线程模型无关 */
public class RetrievalContext {
    public static final String CONTEXT_KEY = "kb.retrieval_context";   // advisor 参数键

    public static RetrievalContext from(Query query) {                 // 检索组件统一入口
        Object v = query.context().get(CONTEXT_KEY);
        return v instanceof RetrievalContext ctx ? ctx : null;
    }

    private String tenantId;
    private volatile Filter.Expression securityFilter;                  // 懒构建 + 双检锁
    private final List<TraceEntry> traceEntries = new CopyOnWriteArrayList<>();  // 双路并行写入

    public Filter.Expression getSecurityFilter() {
        /* 租户隔离 + 软删除过滤（Phase 3 追加 doc_id/dept_id ACL） */
    }
}
```

传递链路（同步/流式/虚拟线程行为一致）：

```
Controller（请求线程）：new RetrievalContext() + JwtUtils 填充 tenantId/userId
  → chatClient.prompt().advisors(spec -> spec.param(CONTEXT_KEY, ctx))
  → RetrievalAugmentationAdvisor.before()：复制进 Query.context
  → HybridDocumentRetriever / ElasticsearchDocumentRetriever / RerankDocumentPostProcessor：
     RetrievalContext.from(query) 消费（过滤 + trace 记录）
  → 流末 Controller 直读同一实例推送 SSE TRACE（第十一章 11.3）
```

非请求入口（kb-eval 评估）不创建实例，`from()` 返回 null，各组件降级为无租户过滤、无 trace（评估期可接受）。

**并发注记**：`HybridDocumentRetriever` 双路并行写入 `traceEntries`，容器必须线程安全（CopyOnWriteArrayList）——v2 原设计的 ArrayList 因写入全部静默失败而未暴露此缺陷。向量路过滤经 `SearchRequest.filterExpression` 按请求携带（`VectorStoreDocumentRetriever` 的 filterExpression supplier 无 Query 入口、无法参数化，故混合检索器直连 VectorStore）。

## 10.3 ElasticsearchDocumentRetriever（ik BM25 路）

自研组件，同样实现 `DocumentRetriever` 语义（因需额外参数 `recallSize`，以本类方法签名暴露，由 `HybridDocumentRetriever` 直接调用，不直接挂 Advisor）。

**ES 索引定义**（`kb_chunks`，ik 中文分词，由 ETL 双写维护——见第九章 9.4）：

```json
{
  "mappings": {
    "properties": {
      "chunk_id":   { "type": "keyword" },
      "doc_id":     { "type": "keyword" },
      "tenant_id":  { "type": "keyword" },
      "content":    { "type": "text", "analyzer": "ik_max_word", "search_analyzer": "ik_smart" },
      "chunk_type": { "type": "keyword" },
      "file_name":  { "type": "keyword" },
      "page_num":   { "type": "integer" },
      "is_deleted": { "type": "boolean" },
      "created_at": { "type": "date" }
    }
  }
}
```

**检索实现**：

```java
package com.enterprise.kb.ai.retriever;

import co.elastic.clients.elasticsearch.ElasticsearchClient;
import org.springframework.ai.document.Document;
import org.springframework.ai.rag.Query;
import org.springframework.stereotype.Component;

import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * ES BM25 检索路 —— ik 中文分词，返回与向量路同构的 Document 列表
 *
 * <p>Document.id = chunk_id（与向量库融合键一致）；
 * BM25 原始分与排名写入 metadata，Document.score 置为 BM25 分。</p>
 */
@Component
public class ElasticsearchDocumentRetriever {

    private final ElasticsearchClient esClient;
    private final ObjectProvider<RetrievalContext> retrievalContext;
    private static final String INDEX = "kb_chunks";

    public List<Document> retrieve(Query query, int size) {
        RetrievalContext ctx = retrievalContext.getObject();
        var response = esClient.search(s -> s
            .index(INDEX)
            .query(q -> q.bool(b -> {
                b.must(m -> m.match(mm -> mm.field("content").query(query.text())));
                b.filter(f -> f.term(t -> t.field("tenant_id").value(ctx.getTenantId())));
                b.filter(f -> f.term(t -> t.field("is_deleted").value(false)));
                // Phase 3: 追加 doc_id/dept_id ACL filter
                return b;
            }))
            .size(size), Map.class);

        var hits = response.hits().hits();
        List<Document> docs = new java.util.ArrayList<>(hits.size());
        for (int i = 0; i < hits.size(); i++) {
            var hit = hits.get(i);
            Map<String, Object> source = hit.source();
            Map<String, Object> meta = new HashMap<>();
            meta.put("chunk_id", source.get("chunk_id"));
            meta.put("doc_id", source.get("doc_id"));
            meta.put("tenant_id", source.get("tenant_id"));
            meta.put("chunk_type", source.getOrDefault("chunk_type", "TEXT"));
            meta.put("file_name", source.get("file_name"));
            meta.put("page_num", source.get("page_num"));
            meta.put("bm25_score", hit.score());
            meta.put("bm25_rank", i + 1);
            meta.put("retrieval_source", "bm25");
            // Document.id = chunk_id：RRF 融合键
            docs.add(new Document((String) source.get("chunk_id"),
                (String) source.get("content"), meta));
        }
        ctx.addTraceEntries("bm25", docs);  // 调试台数据
        return docs;
    }
}
```

**关键设计点**：

- `ik_max_word` 索引 / `ik_smart` 检索的双模式是 ik 的标准实践（细粒度建索引保召回，粗粒度查询保精度）；
- ES 文档由 ETL 管道双写（第九章 9.4），`chunk_id` 与 PG/向量库严格一致，删除走 `is_deleted` 软删同步，物理删除走级联清理（第十四章）；
- BM25 原始分不做归一化——RRF 只消费排名，天然免疫分数尺度差异（这正是选 RRF 而非加权求和的原因）。

## 10.4 RrfFusion 融合算法

Reciprocal Rank Fusion：`RRF_score(d) = Σ 1 / (K + rank_i(d))`，K=60（标准常数，`Constants.RRF_K` 已定义于 kb-commons）。优势：无需分数归一化、对离群分数不敏感、可解释（排名即贡献）。

```java
package com.enterprise.kb.ai.retriever;

import org.springframework.ai.document.Document;
import org.springframework.stereotype.Component;

import java.util.*;

/**
 * RRF 融合器 —— 将双路召回按倒数排名融合为单一有序列表
 *
 * <p>输出 Document 携带完整溯源元数据（双路得分/排名/融合分），
 * 为检索调试台（10.7）与 SSE TRACE 事件（第十一章）提供数据。</p>
 */
@Component
public class RrfFusion {

    public List<Document> fuse(List<Document> vectorHits,
                               List<Document> bm25Hits,
                               int limit) {
        Map<String, FusedEntry> table = new LinkedHashMap<>();

        for (int i = 0; i < vectorHits.size(); i++) {
            Document d = vectorHits.get(i);
            table.computeIfAbsent(d.getId(), k -> new FusedEntry(d))
                 .vectorRank = i + 1;
        }
        for (int i = 0; i < bm25Hits.size(); i++) {
            Document d = bm25Hits.get(i);
            // chunk_id 相同即同一 Chunk；BM25 路补全向量路缺失的 file_name 等字段
            table.computeIfAbsent(d.getId(), k -> new FusedEntry(d))
                 .mergeFrom(d).bm25Rank = i + 1;
        }

        return table.values().stream()
            .peek(FusedEntry::computeFusionScore)
            .sorted(Comparator.comparingDouble(FusedEntry::fusionScore).reversed())
            .limit(limit)
            .map(FusedEntry::toDocument)
            .toList();
    }

    /** 融合中间态：不修改输入 Document，避免共享实例副作用 */
    private static class FusedEntry {
        final String chunkId;
        String content;
        Map<String, Object> metadata;
        Integer vectorRank;
        Integer bm25Rank;
        double fusionScore;

        FusedEntry(Document d) {
            this.chunkId = d.getId();
            this.content = d.getText();
            this.metadata = new HashMap<>(d.getMetadata());
        }

        FusedEntry mergeFrom(Document d) {
            // BM25 路带来的 file_name/page_num 等补入（向量元数据本就携带，取并集）
            d.getMetadata().forEach(this.metadata::putIfAbsent);
            return this;
        }

        void computeFusionScore() {
            double score = 0;
            if (vectorRank != null) score += 1.0 / (Constants.RRF_K + vectorRank);
            if (bm25Rank != null)   score += 1.0 / (Constants.RRF_K + bm25Rank);
            this.fusionScore = score;
        }

        double fusionScore() { return fusionScore; }

        Document toDocument() {
            metadata.put("vector_rank", vectorRank);     // null 表示该路未召回
            metadata.put("bm25_rank", bm25Rank);
            metadata.put("fusion_score", fusionScore);
            return Document.builder()
                .id(chunkId)
                .text(content)
                .metadata(metadata)
                .score(fusionScore)
                .build();
        }
    }
}
```

## 10.5 RerankDocumentPostProcessor（qwen3-rerank 精排）

实现 `DocumentPostProcessor`（签名 `BiFunction<Query, List<Document>, List<Document>>`，经源码核验）。选型 DashScope `qwen3-rerank` API：与 Embedding 同生态（同 API Key、同 base 账号体系）、免 GPU 部署、中文效果强；v1 的"BGE 本地部署 / Cohere"二选一废弃。

```java
package com.enterprise.kb.ai.retriever;

import org.springframework.ai.document.Document;
import org.springframework.ai.rag.Query;
import org.springframework.ai.rag.postprocessor.DocumentPostProcessor;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;
import org.springframework.web.client.RestClient;

import java.util.*;

/**
 * 重排序后处理器 —— DashScope qwen3-rerank API
 *
 * <p>对 RRF 融合后的 recallSize 候选精排并截断至 topK。
 * 服务不可用（未配置 endpoint / 调用失败）时降级为按 fusion_score 截断，不阻塞主链路。</p>
 */
@Component
public class RerankDocumentPostProcessor implements DocumentPostProcessor {

    private final RestClient restClient;
    private final boolean enabled;
    private final String model;

    public RerankDocumentPostProcessor(
            @Value("${rag.rerank.endpoint:}") String endpoint,
            @Value("${rag.rerank.model:qwen3-rerank}") String model,
            @Value("${DASHSCOPE_API_KEY:}") String apiKey) {
        this.enabled = endpoint != null && !endpoint.isEmpty();
        this.model = model;
        this.restClient = enabled
            ? RestClient.builder().baseUrl(endpoint)
                .defaultHeader("Authorization", "Bearer " + apiKey).build()
            : null;
    }

    @Override
    public List<Document> apply(Query query, List<Document> documents) {
        if (!enabled || documents.isEmpty()) {
            return truncateByFusionScore(documents);
        }
        try {
            // 请求/响应结构以 DashScope qwen3-rerank API 文档为准（实现时核验契约）
            var body = Map.of(
                "model", model,
                "input", Map.of(
                    "query", query.text(),
                    "documents", documents.stream().map(Document::getText).toList()),
                "parameters", Map.of("top_n", Constants.DEFAULT_TOP_K,
                                     "return_documents", false));
            RerankResponse resp = restClient.post().body(body)
                .retrieve().body(RerankResponse.class);

            List<Document> reranked = new ArrayList<>();
            for (RerankResult r : resp.output().results()) {
                Document src = documents.get(r.index());
                Map<String, Object> meta = new HashMap<>(src.getMetadata());
                meta.put("rerank_score", r.relevanceScore());
                reranked.add(Document.builder().id(src.getId())
                    .text(src.getText()).metadata(meta)
                    .score(r.relevanceScore()).build());
            }
            return reranked;  // API 已按相关性降序
        } catch (Exception e) {
            log.warn("rerank 调用失败，降级为 fusion_score 截断: {}", e.getMessage());
            return truncateByFusionScore(documents);
        }
    }

    private List<Document> truncateByFusionScore(List<Document> docs) {
        return docs.stream().limit(Constants.DEFAULT_TOP_K).toList();
    }

    record RerankResponse(Output output) {}
    record Output(List<RerankResult> results) {}
    record RerankResult(int index, double relevanceScore) {}
}
```

配置（`application-ai.yml`）：

```yaml
rag:
  rerank:
    endpoint: ${RERANK_ENDPOINT:https://dashscope.aliyuncs.com/compatible-api/v1/reranks}
    model: ${RERANK_MODEL:qwen3-rerank}
  retrieval:
    rewrite:
      enabled: ${RETRIEVAL_REWRITE_ENABLED:true}    # 多轮查询改写，默认开
    expansion:
      enabled: ${RETRIEVAL_EXPANSION_ENABLED:false}  # 多查询扩展，默认关（延迟/token 成本）
```

> **v2 注（可变性与演进）**：重排序实现于 `DocumentPostProcessor` 接口之上，未来切换 Qwen3-Reranker / Jina v3 仅需新增实现 + 配置切换，检索主链路不动。另预留**文档质量分级**演进口：Phase 3+ 增加 rerank 分数阈值截断（如 `rerank_score < 0.3` 的候选不注入 prompt，改走空证据路径），即"检索后文档分级丢弃"的初阶形态（当前 rerank 只排序不截断）。

## 10.6 RetrievalAugmentationAdvisor 组装

在 kb-ai-core 配置类中完成模块化装配，**替代** v1 的 `QuestionAnswerAdvisor`（Phase 1 形态）与手搓 `PrefetchRagAdvisor`（v1 设计形态）：

```java
package com.enterprise.kb.ai.config;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;
import org.springframework.ai.rag.generation.augmentation.ContextualQueryAugmenter;
import org.springframework.ai.rag.preretrieval.query.expansion.MultiQueryExpander;
import org.springframework.ai.rag.preretrieval.query.transformation.RewriteQueryTransformer;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.task.TaskExecutor;

@Configuration
public class RetrievalConfig {

    /** Grounding Prompt：强制证据约束 + [ref-N] 标注约定（与前端溯源卡片配套） */
    private static final String GROUNDING_PROMPT = """
        你是企业知识库专家。必须且只能基于【参考资料】回答问题。

        【回答规则】
        1. 资料包含相关信息时准确回答，每个事实性陈述用 [ref-N] 标注来源编号
        2. 资料无相关信息时明确回答："知识库中未找到相关信息，建议您补充相关文档或换个方式提问"
        3. 信息不足时说明已有信息并指出缺失部分
        4. 禁止编造、猜测或使用外部知识

        【参考资料】
        {context}

        【用户问题】
        {query}
        """;

    @Bean
    public RetrievalAugmentationAdvisor retrievalAugmentationAdvisor(
            ChatClient.Builder chatClientBuilder,
            HybridDocumentRetriever hybridRetriever,
            RerankDocumentPostProcessor rerankPostProcessor,
            TaskExecutor retrievalExecutor,
            @Value("${rag.retrieval.rewrite.enabled:true}") boolean rewriteEnabled,
            @Value("${rag.retrieval.expansion.enabled:false}") boolean expansionEnabled) {

        var builder = RetrievalAugmentationAdvisor.builder()
            .documentRetriever(hybridRetriever)
            .documentPostProcessors(List.of(rerankPostProcessor))
            .queryAugmenter(ContextualQueryAugmenter.builder()
                .promptTemplate(/* 封装 GROUNDING_PROMPT 的 PromptTemplate */)
                .emptyContextPromptTemplate(/* 无变量占位符的拒绝模板：render() 无参调用 */)
                .allowEmptyContext(false)   // v2.1 核验修正：true = 空证据时原样返回问题由模型自由作答（负向用例必然幻觉）；
                                            // false + 拒绝模板 = 确定性拒答（16.4 Negative Rejection 关键机制，实测 0.80→1.00）
                .build())
            .taskExecutor(retrievalExecutor)   // 虚拟线程执行器
            .order(500);                        // 记忆(400)之后、工具调用(1000)之前

        if (rewriteEnabled) {
            builder.queryTransformers(List.of(RewriteQueryTransformer.builder()
                .chatClientBuilder(chatClientBuilder)
                .build()));
        }
        if (expansionEnabled) {
            builder.queryExpander(MultiQueryExpander.builder()
                .chatClientBuilder(chatClientBuilder)
                .numberOfQueries(3)
                .build());
        }
        return builder.build();
    }

    @Bean
    public TaskExecutor retrievalExecutor() {
        return new org.springframework.core.task.VirtualThreadTaskExecutor("retrieval-");
    }
}
```

> **API 可信度标注**：本章框架 API（`RetrievalAugmentationAdvisor`、`DocumentRetriever`、`DocumentPostProcessor`、`VectorStoreDocumentRetriever`、`RewriteQueryTransformer`、`MultiQueryExpander`、`ContextualQueryAugmenter`、`ConcatenationDocumentJoiner`）均于 2026-07-31 对照 v2.0.0 GA 源码逐一核验存在。Builder 选项细节（`numberOfQueries`、`allowEmptyContext`、`filterExpression` supplier 重载）在实现时以 Javadoc 最终确认为准。

**多查询扩展默认关闭的取舍**：扩展会将检索调用与 embedding 调用放大 N 倍，对 TTFT（目标 < 1.5s）不友好；`RRF` 融合结构本身已为扩展留好接口（`DocumentJoiner` 语义按 query 分组），需要时打开配置即可，`ConcatenationDocumentJoiner`（框架内置）负责跨查询变体合并。

## 10.8 性能与容量基线

| 指标 | 目标 | 手段 |
|---|---|---|
| 单次检索总延迟（10 万级 Chunk） | < 200ms（P95） | 双路并行，总延迟 = max(向量, BM25) + rerank |
| 单路超时 | 5s | 超时即降级为空，不阻塞 |
| 重排序开销 | ~200ms（10 候选） | qwen3-rerank API；失败降级 fusion_score 截断 |
| TTFT 影响 | 检索链路 < 400ms | expansion 默认关；rewrite 为轻量 LLM 调用 |
| ES 索引规模 | 千万级 Chunk 内单索引胜任 | 超出按 tenant_id 分索引（Phase 4 预案） |
