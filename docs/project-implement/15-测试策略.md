## 15.2 Testcontainers 集成测试

```java
@SpringBootTest
@Testcontainers
class HybridDocumentRetrieverIntegrationTest {
    
    @Container
    static PostgreSQLContainer<?> pg = new PostgreSQLContainer<>("postgres:18");
    
    @Container
    static MilvusContainer milvus = new MilvusContainer("milvusdb/milvus:v2.6");
    
    @Container
    static ElasticsearchContainer es = new ElasticsearchContainer("elasticsearch:9.4.2");
    
    @Container
    static GenericContainer<?> redis = new GenericContainer<>("redis:8.0")
        .withExposedPorts(6379);
    
    @DynamicPropertySource
    static void configureProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", pg::getJdbcUrl);
        registry.add("kb.vector-store.provider", () -> "milvus");
        registry.add("kb.vector-store.milvus.host", milvus::getHost);
        registry.add("spring.elasticsearch.uris", 
            () -> "http://" + es.getHost() + ":" + es.getMappedPort(9200));
        registry.add("spring.data.redis.host", redis::getHost);
    }
    
    @Autowired
    private HybridDocumentRetriever hybridRetriever;
    
    @Test
    void shouldReturnFusedResultsWithBothSources() {
        // Given: 准备测试数据（文档经完整 ETL：向量化 + ES 双写）
        seedTestDocuments();
        
        // When: 执行混合检索（DocumentRetriever 语义，返回带溯源元数据的 Document）
        List<Document> results = hybridRetriever.retrieve(
            new Query("如何配置 Spring Boot 数据源？"));
        
        // Then: 融合结果携带双路得分元数据（10.1 元数据约定）
        assertThat(results).hasSizeGreaterThanOrEqualTo(1);
        assertThat(results.get(0).getMetadata().get("fusion_score"))
            .asInstanceOf(DOUBLE).isGreaterThan(0);
        assertThat(results).anyMatch(d -> d.getMetadata().get("vector_rank") != null);
        assertThat(results).anyMatch(d -> d.getMetadata().get("bm25_rank") != null);
    }
}
```

## 15.4 Gatling 压测（簇⑥ 4.12，v2.59）

> **新口径（v2.29 复审定案）**：QPS 口径废止 → 检索真压 P95 / 生成桩压 / 小样本真实 LLM TTFT·TPOT / 并发 SSE 稳定；验收线见 18 §18.4，执行步骤见用户侧清单 LT1，报告落 `docs/reports/loadtest/`。

**模块形态**：独立模块 `kb-loadtest` —— gatling-charts-highcharts 3.15.1（Java DSL）+ gatling-maven-plugin 4.21.10，test scope 声明；`gatling:test` 显式触发不绑生命周期阶段；Simulation 类命名 `*Simulation`（surefire 匹配域外）→ 根聚合 `mvn test` 只编译（含桩契约单测）不跑压测场景。参数全经 `-Dloadtest.*` > `LOADTEST_*` env > 缺省值（LoadTestConfig 单源解析），注入规模/阈值可调。

**四场景**：

| 场景 | 压测对象 | 注入形态 | 断言（Gatling assertions 内建） |
|---|---|---|---|
| A 检索真压 | POST /api/v1/retrieval/search（直调检索链，不经生成） | open：constantUsersPerSec（缺省 3 rps × 60s） | P95 < 500ms + 零失败 |
| B 生成桩压 | /chat/stream 全链（生成段接桩） | closed：50 并发 ramp + hold（缺省 120s） | 零失败（await DONE，请求时延 = 全对话） |
| C 真实 LLM 小样本 | /chat/stream 真实主模型 | 1 用户 × 10 样本串行 | TTFT P95 < 2s + TPOT < 100ms |
| D SSE 长会话 | /chat/stream 20 并发 + sessionId 多轮记忆复用 | closed：20 并发持续窗口（缺省 180s） | 零失败 + 全 DONE 收口 |

场景 C **计费敏感缺省关闭**——构造期即拒跑，须 `-Dloadtest.c.enabled=true` 显式确认（执行前用户确认口径）。TTFT = await 首 TOKEN 帧的请求时延（与服务端 rag.ttft 同源不同层）；TPOT = drain 阶段 TOKEN 帧到达时间戳差分均值。

**SSE 协议对齐（源码级核验定案，簇计划风险点③清偿）**：

- Gatling 3.15 SSE 消息形态 = `ServerSentEvent.asJsonString`：无名帧 `{"data":{...}}`、命名帧 `{"event":"TRACE","data":{...}}`，data 为 JSON 时原样内嵌 → jmesPath(`data.token`) / (`data.messageId`) 直匹配 TOKEN/DONE 帧（ChatProtocol.firstTokenCheck/doneCheck）。
- 桩通道 OpenAI 终帧 `data: [DONE]` 非 JSON（序列化后为非法 JSON 文本）→ 经 processUnmatchedMessages 原文扫描判别（对齐官方 LLM API 指南形态），不做 jmesPath 匹配。
- 帧判别（drainAndInspect）基于 record 声明序确定性序列化形态 TokenEvent(token) / ErrorEvent(error) / DoneEvent(messageId, traceId)，结构化键位判别，防 TRACE 溯源 snippet 文本含同名字面量误判。
- drain 循环条件 = 未 DONE ∧ 无 ERROR ∧ 安全窗口内（drainCondition）——兜底半挂流（连接存活但停帧）的无限自旋。
- closed 注入会话跨迭代复用 → 每轮对话前 resetInspection 重置判别态 + SSE 未匹配缓冲扩容（await DONE 期间全部 TOKEN 帧入缓冲）。

**生成桩 StubChatServer**：纯 JDK HttpServer + 虚拟线程执行器，零第三方依赖、源码单文件可启动（`java StubChatServer.java --port 9988`）；OpenAI `chat.completion.chunk` 全契约：delta chunks → finish_reason stop → usage chunk（`stream_options.include_usage` 契约，流式计账消费）→ `data: [DONE]`；token 数/帧间隔/首帧延迟参数化。场景 B/D-桩形态以桩替代主模型端点（kb-api `DEEPSEEK_BASE_URL` 指向桩，容器经 host.docker.internal），真实检索/护栏/配额链全程在路、零真实 LLM 计费；StubChatServerTest 3 单测钉契约。

**执行纪律**：首跑 SmokeProbeSimulation 连通探针（1 VU：health → 检索调试 → SSE 全链走通），通过后依序 A → B → D → C；JWT 经前端 localStorage 获取注入（owner claim 定租户），压测不自造令牌、token 过期即 401 快速失败；**语料纪律（敏感词红线）**：`loadtest-queries.json` = Golden **干净集**按 ID 引用抽取 21 条（生成期过滤引号/反斜杠/EL 符），注入集语料零接触；请求体函数形态装配（JSON 转义，规避 EL 插值问题）。
