# 05 · 平台规模化与高可用

> 状态：设计预案（未立项）· 基线：ECS 单机（2C/8G）容器化全栈 + 99.5% 可用性口径 + 灾备最小集（PG 备份双副本 + 恢复演练）· 触发条件：并发规模增长 / 多节点预算到位

## 1. 现状盘点

| 面 | 现状 | 规模化就绪度 |
|---|---|---|
| 部署形态 | 单机 docker compose 全栈（app+监控）+ kb-stack 单 unit 自启 | 单机定型（K8s 目标形态 17.1 草图降级附录留档） |
| 可用性 | 99.5%（单机现实口径）；健康检查/自动重启/reboot 自愈/备份恢复演练全过 | 单机天花板 |
| 应用无状态性 | 对话链全无状态（参数链纪律，不用 ThreadLocal/@RequestScope） | ✅ 多实例就绪 |
| 状态面 | PG（事实源）/ Redis（记忆/限流/审批/任务表/缓存——**天然多实例共享**）/ MinIO / Milvus / ES / Neo4j | Redis 族 ✅ 跨实例 |
| 单机粘性点 | ETL 进度 WebSocket（进程内推送）/ 图抽取 JVM 信号量 / 审计 auditExecutor（单进程异步） | 🟡 三处需改造 |
| 观测 | 指标/告警/面板/trace 全链 | ✅（多实例下补实例维度标签） |

## 2. 目标形态（演进阶梯）

```
L0 现状：单机 99.5% ✅
L1 双实例：应用层双副本 + LB（SSE 长连接保持）→ 应用单点消除，滚动升级零停机
L2 数据面高可用：PG 主备 / Redis 哨兵或集群 / Milvus 集群 → 99.9% 口径成立
L3 K8s 形态：Helm 化 + HPA + 就绪探针编排 → 弹性与运维标准化（17.1 草图复活）
```

**判据纪律**：L1/L2/L3 各自由真实负载触发，不做预迁移（对齐「不预建空表空列」归档纪律——每一级都有明确的业务判据：L1 = 单机 CPU 饱和或滚动升级需求；L2 = 数据面单点故障容忍度要求；L3 = 多服务编排与弹性伸缩需求）。

## 3. 市面主流技术对照（2026）

| 方向 | 主流形态 | 对照结论 |
|---|---|---|
| Java 应用水平扩展 | 无状态服务 + LB 是基线；虚拟线程（本项目已用）在同步阻塞链路下吞吐优势明显 | 三处单机粘性点改造后即可双实例（§4.1） |
| SSE 长连接 LB | nginx/HAProxy 长连接超时与粘性；或网关层无粘性（连接各自独立，事件流自带会话键） | 本项目 SSE 事件流无连接内状态依赖（会话在 Redis）——**无粘性 LB 直配** |
| 数据面 | PG 主备（Patroni/cloud 腾挪）/ Redis Sentinel/Cluster / Milvus 分布式（17.2 草图） | 按云托管优先（ECS 侧托管版省运维），自建次之 |
| 编排 | K8s + Helm 为企业标准；Serverless 容器（按需扩缩）兴起但长连接/流式负载亲和性一般 | L3 走标准 K8s；SSE 场景 HPA 按连接数自定义指标 |
| 可观测多实例 | OpenTelemetry 全家桶 + 实例标签 | 既有 OTLP 通道补 `instance` 维度即可 |

## 4. 设计方案

### 4.1 L1 双实例改造清单（三处粘性点）

| 粘性点 | 现状 | 改造 |
|---|---|---|
| ETL 进度 WS | 进程内订阅推送 | 改 Redis pub/sub 广播（`rag:etl:progress:{docId}`）——各实例 WS 网关订阅转发，任一实例连接均收进度 |
| 图抽取并发闸 | JVM Semaphore 3 在飞 | 改 Redis 分布式信号量（Redisson `RSemaphore`）——跨实例总在飞约束供应商压力语义不变 |
| 审计异步执行器 | 单进程 auditExecutor | 无需改造（各实例独立异步落库，PG 写入天然并发安全）——仅确认连接池上限 |

改造量约 2-3d；其后双实例 + nginx upstream（`least_conn`，SSE 超时放宽）即成。

### 4.2 L2 数据面高可用

- **PG**：云 RDS 主备（优先）或自建 Patroni；应用侧零改动（JDBC 单端点/代理端点）；
- **Redis**：云托管版或 Sentinel（`spring.data.redis` 哨兵形态配置）；Redisson 哨兵兼容；
- **Milvus/ES**：云托管多副本；Milvus 集群形态（17.2 降级草图复活——依赖 etcd/对象存储组件）；
- **MinIO**：分布式纠删码或云 OSS 替代；
- **判据**：全链路依赖双副本后，可用性口径 99.5%→99.9% 重定（SLA 面板与兜底自检清单同步）。

### 4.3 L3 K8s 形态（17.1 草图复活）

- **资产**：Helm chart（app/前端/监控三块；PG/Redis/Milvus 等数据面以云服务或独立 chart）；`kb-stack.service` 语义 → Deployment+HPA+PDB；Compose 与 Helm 双形态并存（小规模用户仍可 compose 起单机——对齐「缺省最小形态」纪律）；
- **弹性**：HPA 按 CPU + SSE 活跃连接自定义指标；就绪探针 = actuator health（已有）；
- **发布**：滚动升级零停机（L1 双实例为前提）+ 版本回滚；
- **前提判据**：运维团队能力与节点预算——不为 K8s 而 K8s（单机形态已满足当前规模）。

### 4.4 成本经营（不升规模的平行杠杆）

- **语义缓存命中率运营**：`rag.retrieval.cache.hit/miss` 从观察面转目标面（>30% 验收线复检；阈值调优 + 高频问句运营）；
- **供应商前缀缓存**：DeepSeek 形态前缀缓存读数确认（N1 挂起项）；
- **GLM-Flash 成本带**：主答成本曲线持续跟踪（token/问答审计数据面已有）；
- **批处理错峰**：图抽取/重建等批任务限流档位（已有）按供应商折扣时段调优。

## 5. 实施路径

| 批 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| L1-a | 三粘性点改造（WS 广播/分布式信号量/审计确认） | — | 单机回归全绿（多实例就绪度单测钉死） |
| L1-b | 双实例 + LB 部署 + SSE 压测复跑 | L1-a + LB | 场景 B/D 双实例压测零失败；滚动升级零停机演练 |
| L2 | 数据面双副本（云托管优先） | 预算 | 主备切换演练；99.9% 口径重定 + 兜底自检清单更新 |
| L3 | Helm chart + HPA + 滚动发布 | K8s 集群 | K8s 形态全栈冒烟 + 弹性压测 |

**风险**：Milvus 集群运维复杂度（10 章否决纪要的历史提醒——云托管优先自建）；SSE 长连接在 HPA 缩容时的排水（terminationGracePeriod + 连接迁移提示，产品层配合）。
