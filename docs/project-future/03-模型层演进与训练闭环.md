## 2. 差距与演进方向

1. **轻量档缺位**——三级路由（5.4-B 归档）与闲聊直答升质量都受益于一个低成本高速度档；当前两档（主答/辅助）已定谳「形同虚设」，第三档引入才解锁；
2. **数据合规场景无本地形态**——部分企业语料不可出境；当前全云 API 形态不满足；
3. **训练闭环断链**——导出的 SFT/DPO 数据无下游（微调→回评→上线全流程缺失），数据飞轮只转了一半；
4. **多模态文档理解**——图表/扫描件经 OCR 间接理解，信息损失（版式/图表语义）；VLM 直接视觉理解是 2025-2026 主流演进；
5. **模型升级依赖手工**——MB1 流程未工具化。

## 4. 设计方案

### 4.1 本地开源模型形态（数据合规场景）

- **部署**：vLLM 容器（GPU 节点）跑开源主答（GLM/Qwen 开源版）+ BGE embedding/reranker——OpenAI 兼容端点；
- **接入**：零代码——`ZHIPU_API_KEY`→本地端点 env 组切换；辅助族可保持云 API（非敏感面）或全本地；
- **代价面**：GPU 成本（单卡可服务 7B-14B 量化档）；质量门禁重锚（MB1 协议跑一轮，阈值线按新模型实测定档——GLM 0.75/8% 与 DeepSeek 0.85/5% 双先例的第三形态）；
- **定位**：合规驱动的可选形态，不默认推荐（云 API 的质量/成本曲线当前更优）。

### 4.2 轻量档模型与三级路由复活（5.4-B）

- **触发**：引入第三档（本地小模型或更便宜云档）；
- **形态**：`SmartRoutingChatModel` 档位扩展（heavy/light 两档主答 + 既有辅助族）；闲聊直答（CHITCHAT 路径）升轻档生成、简单事实问轻档试答+置信回落重档——**先落「闲聊升档」单一场景验证价值，再议全链三级**（避免 3.2「形同虚设」判据复现）；
- **复活提醒**（归档在案）：跨厂商转发以备用 options 重建 Prompt（坑位⑭）+ kb-eval 防误路由护栏。

### 4.3 训练闭环全流程（数据飞轮转正）

```
反馈积累（已运行）──▶ 导出 SFT/DPO（已就绪）──▶ 微调执行（本节补）
                                                     │ 云：百炼托管微调（LoRA）
                                                     │ 本地：LLaMA-Factory（QLoRA 单卡）
                                                     ▼
                       灰度切流 ◀── A/B 门禁对比（已内建）◀── 新模型注册（本节补）
```

- **微调执行**：先云托管（百炼——导出格式已对齐 ChatML；零运维）；规模化后本地 LLaMA-Factory（DPO 数据直喂）；
- **新模型注册**：微调产物（云 endpoint 或本地 vLLM）按新 provider 形态注册，`rag.routing.primary.provider` 新增枚举；
- **灰度**：A/B 快照 diff（eval-diff 已有）+ 生产灰度（按租户百分比路由新旧 provider——SmartRouting 形态扩展）；
- **节奏**：季度级——反馈量达门槛（SFT≥100/DPO≥50 对）即可起一轮，微调收益以门禁读数裁决（不达基线则弃，数据继续积累）。

### 4.4 多模态文档理解（VLM 路线）

- **切入点**：解析支线新增 **VLM 路由**（SmartParsingRouter 第四路）——图表密集/扫描件 PDF 直接 VLM 逐页理解出结构化 markdown（版式/图表语义保真），替代 OCR 密度判定路径；
- **模型**：Qwen-VL / GLM-4V 类（vLLM 或云 API）；成本高于 OCR 路由，按页数限流；
- **评估**：Golden 多模态专项集（图表问答锚点）对比 OCR 路由召回/答案质量；
- **远期**：多模态 embedding（图文混合向量）入检索——与 04 分册 §3 ColPali 路线合并评估。

### 4.5 模型升级协议工具化

- 把 MB1 流程固化为 kb-eval 子命令：`--eval.model-upgrade=<provider>` = 五验冒烟清单输出 + 门禁全量跑 + 与当前基线 diff 报告 + 阈值重锚建议（人工审定）；
- 价值：季度级模型升级从「会话驱动手工多轮」变为「一条命令一轮评审」。

## 5. 实施路径

| 批 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| 批1 | 训练闭环（云托管微调 + 新模型注册 + 灰度路由） | 反馈量达标 | 一轮完整闭环 E2E：导出→微调→A/B 门禁→灰度；收益门禁裁决在档 |
| 批2 | 模型升级协议工具化（MB1 固化子命令） | — | 新 provider 升级一轮走完工具化流程 |

| 批4 | 本地开源模型形态（vLLM + 合规切换） | GPU 资源 | 合规场景全本地冒烟 + 门禁第三形态定档 |
