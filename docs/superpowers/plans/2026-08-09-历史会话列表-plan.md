# 实现计划：历史会话列表 + 溯源恢复 + 真续聊

> Spec：docs/superpowers/specs/2026-08-09-历史会话列表-design.md（f0005df，用户已批准）
> 核验结论（落码依据）：ChatMemory API = get/add/clear（FaultTolerantChatMemory 已包裹 agentChatMemory Bean，回填经 Bean 即自带容错）；RedissonClient Bean 可直接注入（TokenBudgetAdvisor 同款）；KbFeedback.rating 为 FeedbackRating 枚举；归属校验模式参照 FeedbackService（隐藏存在性）；测试为纯 Mockito + AssertJ 风格

## 任务分解（按依赖顺序）

### T1 kb-domain 仓储 + kb-api DTO
- KbSessionRepository：+`Page<KbSession> findByTenantIdAndUserIdOrderByUpdatedAtDesc(String, String, Pageable)`
- KbMessageRepository：+`List<KbMessage> findTop20BySessionIdOrderByCreatedAtDesc(String)`（回填用，读取后反转为升序）
- KbFeedbackRepository：+`List<KbFeedback> findByMessageIdInAndUserId(List<String>, String)`
- dto/SessionItem：`record SessionItem(String id, String title, Integer messageCount, LocalDateTime updatedAt)`
- dto/HistoryMessageItem：`record HistoryMessageItem(String id, String role, String content, LocalDateTime createdAt, List<AgentStreamEvent.SourceTrace> sources, String traceId, String feedback)`（sources/traceId/feedback 仅 assistant 非空）

### T2 ChatSessionService 扩展（kb-api）
构造注入新增：`@Qualifier("agentChatMemory") ChatMemory`、`RedissonClient`、`KbFeedbackRepository`、`JsonMapper`（tools.jackson，注意事项⑬）

1. **archiveTurn 签名**：`(..., String assistantMessageId, AgentStreamEvent.TraceEvent traceEvent, String traceId)`
   - assistant 消息：citations = `jsonMapper.writeValueAsString(traceEvent)`（traceEvent null 或序列化异常 → null + warn）；metadata = traceId 非空时 `{"traceId":"..."}`（JsonMapper 写 Map）
   - user 消息 citations/metadata 不动
2. **reseedMemoryIfAbsent(String sessionId)**（public，供 Controller 调用）：
   - 全程 try-catch fail-open（warn 日志）
   - 守卫：`redissonClient.<String>getBucket("rag:session-reseed:" + sessionId).trySet("1", 30, TimeUnit.SECONDS)` false → return
   - `memory.get(sessionId)` 非空 → return；PG `findTop20...Desc` 空 → return
   - 反转升序 → USER→UserMessage / ASSISTANT→AssistantMessage（空 content、未知 role 跳过）→ `memory.add(sessionId, msgs)` + info 日志
3. **listSessions(tenantId, userId, page, size)**：size 上限 100、page 负值归零 → PageRequest → 映射 SessionItem
4. **loadMessages(sessionId, tenantId, userId)**：findById → 不存在/tenant/user 不符抛 `SESSION_NOT_FOUND`；消息升序；assistant 条目解析 citations（`jsonMapper.readValue(citations, TraceEvent.class).sources()`，异常 warn + null）、从 metadata JSON 提 traceId（Map 读取，异常容忍）；feedback 经 findByMessageIdInAndUserId 批量映射
5. **deleteSession(sessionId, tenantId, userId)**：归属校验同上 → deleteById → try-catch `memory.clear(sessionId)`

### T3 SessionController + AgentController
- **SessionController**（/api/v1/sessions，@RequiredArgsConstructor：ChatSessionService + JwtUtils）：
  - 私有 `requireIdentity()`：tenantId 空白 → IDENTITY_INCOMPLETE（复制 AgentController 守卫语义）
  - GET ``（list）/ GET `/{id}/messages` / DELETE `/{id}`，响应 ApiResponse 包裹
- **AgentController**：
  - `chat()`：newRetrievalContext 后 `chatSessionService.reseedMemoryIfAbsent(sessionId)`；archiveTurn 传 `traceCtx.isSkipRetrieval() || toolMode ? null : safeBuildTrace(traceCtx)` + `ctx.getTraceId()`
  - `chatStream()`：同样前置 reseed；doOnComplete 的 archiveTurn 同参数（toolMode/skipRetrieval 判定）

## 风险位
- JsonMapper record 反序列化：Jackson 3 原生支持 record（Spring Boot 4.1 默认 mapper 即 Jackson 3），roundtrip 测试兜底
- Redisson RBucket.trySet(V, long, TimeUnit)：Redisson 4.x 稳定 API；若编译不符回落 setIfAbsent 形态（RBucket 无则用 RAtomicLong compareAndSet(0,1)+expire 等价单发）
- ddl-auto=validate：本功能零表结构变更（citations/metadata 列早已存在），无 ALTER
- 归档异步竞态：DONE 后 1s 延迟刷新列表（spec 定案），不做乐观条目
