# 历史会话列表 + 溯源恢复 + 真续聊 — 设计文档

> 日期：2026-08-09 · 归属：补齐 3.15 清单缺口（ChatSessionService javadoc 已锚定「前端历史会话列表」）· 设计版本回写目标：11 章 v2.17

## 1. 背景

前端当前无历史会话列表：刷新页面或点「新对话」后，已归档到 PG 的会话（kb_session/kb_message，3.1 异步旁路归档）无法再次打开，更无法对历史回答溯源或继续对话。数据层已就绪：

- `kb_session`：tenant_id / user_id / title（首轮问题前 50 字符）/ message_count / updated_at，索引 `(user_id, updated_at DESC)` 现成
- `kb_message`：session_id / role / content / **citations JSONB（预留列，从未填充）** / metadata JSONB / id（assistant 消息 id = SSE DONE 帧 messageId，kb_feedback 外键可解析）
- 设计文档附录 C 已预留端点锚点：会话列表（P1）、历史消息（P1）、删除会话（P2）

**核心缺口**：
1. `kb_message.citations` 归档时未写入 → 历史回答无溯源数据可恢复
2. Redis 记忆 TTL 24h（RedisChatMemoryRepository）→ 久未活动的会话续聊时模型丢失多轮上下文

## 2. 需求定案（用户拍板）

| # | 决策点 | 定案 |
|---|--------|------|
| 1 | 过期会话续聊语义 | **PG 回填记忆，真续聊**：记忆为空且 PG 有消息时惰性回填最近 20 条（与窗口同规），对前端透明 |
| 2 | UI 形态 | **对话页内左侧栏，可收起**（ChatGPT 式常驻面板） |
| 3 | 会话删除 | **纳入本次，硬删**（外键 CASCADE 级联消息） |
| 4 | 历史反馈回显 | **回显已有评价**（messages 接口联查 kb_feedback） |

## 3. 方案定案：归档时写 citations（方案 A）

溯源数据来源三选一定案为 **A：归档时写 `kb_message.citations`**：

- Controller 复用现有 `safeBuildTrace(traceCtx)` 投影（与 SSE TRACE 帧同形：三路 sources + chunks + docId + 分数），序列化后随归档写入 assistant 消息 citations 列
- 历史消息接口原样返回 → 前端直接作为 `Message.sources` 消费，`[ref-N]` ↔ final 序列下标对齐契约天然保持，点击徽标弹原文零适配

否决项：
- **B 读取时反查 kb_audit_log**：kb_message 无 trace_id 列，关联只能靠时间+内容模糊匹配；audit chunks 形态 ≠ TRACE 三路形态，final 序列重建与 `[ref-N]` 对齐有风险；审计表有脱敏/降级缺口，是运维视角表，不当产品读取事实源
- **C 历史不恢复溯源**：不满足「打开历史会话进行溯源」原始诉求

## 4. 后端设计

### 4.1 归档链扩展

**`ChatSessionService.archiveTurn`** 增参 `String citationsJson`（可空）：assistant 消息 `setCitations(citationsJson)`；metadata 写 `{"traceId": "<本轮 traceId>"}`（traceId 可空则不写该键）。user 消息 citations 恒 null。

**`AgentController`** 两处调用点（同步 `chat()` / 流式 `chatStream()` 的 `doOnComplete`）：
- rag 链且非免检索（`!traceCtx.isSkipRetrieval()`）：`jsonMapper.writeValueAsString(safeBuildTrace(traceCtx))` 传入
- tool 链 / 免检索直答：传 null
- 序列化用 **`tools.jackson.databind.json.JsonMapper`**（Spring Boot 4.1 Jackson 3，注意事项⑬；注入具体类，勿用 com.fasterxml ObjectMapper）
- 序列化失败 try-catch 降级 null + warn（溯源是旁路增值数据，不击穿归档）

### 4.2 会话 API（新增 `SessionController`，`/api/v1/sessions`）

路径前缀沿用既有扁平实现惯例（`/api/v1/chat`、`/api/v1/feedback` 同款；附录 C 的 `/api/v1/agent/sessions` 为草图锚点，实现后回写注记）。身份一律经 JwtUtils 取 tenantId/userId；tenantId 缺失抛 `IDENTITY_INCOMPLETE`（与 AgentController 同款 fail-closed）。

**GET `/api/v1/sessions?page=0&size=50`**（page 为 0 基页码，前端「加载更多」递增 page）
- 查询：`findByTenantIdAndUserIdOrderByUpdatedAtDesc(tenantId, userId, PageRequest.of(page, size))`（新增仓储方法，tenant+user 双过滤——现有 findByUserId 无租户过滤，不可复用）
- size 上限 100（超出截断为 100）；page 负值归零
- 响应 `data: [{ id, title, messageCount, updatedAt }]`，按 updated_at 倒序

**GET `/api/v1/sessions/{id}/messages`**
- 归属校验 fail-closed：session 不存在 或 tenantId/userId 不匹配 → 404 `SESSION_NOT_FOUND`（不泄露存在性，与 FeedbackService MESSAGE_NOT_FOUND 同纪律）
- 消息按 created_at 升序；每条：`{ id, role, content, createdAt }`，assistant 额外：
  - `sources`：citations JSON 解析为 SSE TRACE 同形结构（复用 `AgentStreamEvent.TraceEvent` 类型反序列化）；citations 为 null 或解析失败 → null（解析失败 warn 日志）
  - `messageId`：即 kb_message.id（反馈提交定位键，复用 3.17 链路）
  - `traceId`：metadata 中提取（反馈回填审计行用），可空
  - `feedback`：联查 kb_feedback（`findByMessageIdInAndUserId(messageIds, userId)` 新增仓储方法，一次批量查）回显当前用户最近评价 `'POSITIVE'|'NEGATIVE'|null`
- user 消息：`{ id, role, content, createdAt }`（无附加字段）

**DELETE `/api/v1/sessions/{id}`**
- 归属校验同上（404）→ `sessionRepository.deleteById`（kb_message 外键 `ON DELETE CASCADE` 级联清消息）
- 顺带 `agentChatMemory.clear(sessionId)`（try-catch 旁路，Redis 抖动不影响删除结果）
- 响应 `data: { deleted: true }`

### 4.3 记忆回填（续聊核心）

**`ChatSessionService.reseedMemoryIfAbsent(String sessionId)`**，由 AgentController `chat()` / `chatStream()` 两入口在身份解析后、服务调用前统一调用：

```
1. try-catch 全程包裹，任何异常 warn + 返回（fail-open，最坏=现状）
2. 单发守卫：Redisson RBucket "rag:session-reseed:{sessionId}" trySet("1", TTL 30s)
   —— false 表示并发回填进行中，直接返回（防 check-then-act 双写重复历史）
3. memory.get(sessionId) 非空 → 返回（热会话零开销路径）
4. PG 查最近 20 条消息（findTop20BySessionIdOrderByCreatedAtDesc 后反转为升序）
   —— 空 → 返回（真·新会话）
5. 映射 KbMessage → Spring AI Message：USER→UserMessage、ASSISTANT→AssistantMessage
   （content 为空串的消息跳过；role 未知值跳过 + warn）
6. memory.add(sessionId, messages)
7. info 日志记录回填条数（观测点）
```

注入：`@Qualifier("agentChatMemory") ChatMemory`（多 ChatClient/ChatMemory Bean 纪律，显式 Qualifier）+ RedissonClient（TokenBudget/RateLimit 同款 Bean）+ KbMessageRepository。

**时序正确性**：回填发生在 Advisor 链执行前，MessageChatMemoryAdvisor(400) 读到的已是回填后的完整窗口；本轮结束后正常写记忆 + 归档，与热会话行为收敛一致。

## 5. 前端设计

### 5.1 API 层（`api/index.ts`）

```ts
export interface SessionSummary { id: string; title: string; messageCount: number; updatedAt: string }
export interface HistoryMessage {
  id: string; role: 'USER' | 'ASSISTANT'; content: string; createdAt: string
  sources?: Source[] | null        // assistant：citations 解析结果，SSE TRACE 同形
  traceId?: string | null          // assistant：审计关联
  feedback?: 'POSITIVE' | 'NEGATIVE' | null
  // 注：反馈定位键即 id（assistant 的 kb_message.id = SSE DONE messageId），
  // 前端映射时 messageId = m.id，DTO 不重复携带
}
listSessions(offset, size) / getSessionMessages(id) / deleteSession(id)
```

### 5.2 store（`stores/chat.ts`）

新增 `openSession(id: string, messages: Message[])`：置 sessionId + messages（整替）。`newSession()` 不变。

### 5.3 新组件 `SessionList.vue`

- props：`activeId`（当前 sessionId）、`disabled`（流式中禁切换）；emits：`select(id)`、`deleted(id)`
- 挂载时拉 `listSessions(0, 50)`；条目：title 单行省略 + 相对时间（x分钟前/x小时前/x天前，本地小工具函数）+ hover 显示删除图标（el-popconfirm 二次确认）
- 当前会话高亮；滚动到底「加载更多」（page 递增，返回数 < size 则止）
- 收起态：整栏收起仅留一条竖排展开按钮；展开/收起状态组件内 ref 即可（不持久化）
- 对外暴露 `refresh()`（供 Chat.vue 在轮次完成后调用）

### 5.4 Chat.vue 接线

- 布局改 flex 行：`<SessionList />` + 现有主列（页头/消息区/输入区）不动
- `select(id)`：`getSessionMessages(id)` → 映射 `HistoryMessage[]` → `Message[]`：
  - role 归一小写；user 仅 content
  - assistant：`sources = m.sources ?? undefined`、`traceOpen = !!sources?.length`（与实时轮行为一致）、`messageId = m.id`、`traceId`、`feedback` 回显
  - `store.openSession(id, mapped)` + scrollToBottom
  - 请求失败：ElMessage.error，不切换会话
- `ask()` DONE 后 `setTimeout(() => sessionListRef.refresh(), 1000)`（归档是异步旁路，延迟防竞态空窗；新会话首轮此时 title 已落库）
- `deleted(id)`：若删的是当前会话 → `newChat()` 重置
- 流式中（`streaming === true`）：SessionList `disabled` 禁切换

### 5.5 复用零适配项

`[ref-N]` 点击（事件委托 data-ref ↔ sources.final 下标）、溯源面板渲染、原文对话框（docId）、👍/👎 提交（messageId 即 PG 主键，upsert 语义）——历史消息与实时轮同一渲染/交互链路。

## 6. 错误处理与降级总表

| 场景 | 行为 |
|------|------|
| citations 序列化失败 | warn + null（历史无溯源面板，降级同旧数据） |
| citations 解析失败 | warn + sources=null |
| 记忆回填任何异常 | warn + 跳过（最坏=现状，不击穿问答） |
| 并发回填竞争 | SETNX 守卫，后到者直接返回 |
| 归属校验失败（跨租户/他人会话） | 404 SESSION_NOT_FOUND（不泄露存在性） |
| Redis 故障时删除会话 | DB 删除成功即可，memory.clear 旁路容错 |
| 会话列表拉取失败 | ElMessage.error + 空态 |

## 7. 安全与隔离

- 所有端点 tenantId+userId 双维度过滤/校验（3.9/3.10 fail-closed 纪律延伸）；tenantId 缺失 IDENTITY_INCOMPLETE
- 历史消息内容为归档时已脱敏形态（archiveTurn 收 safeQuery），无新增泄露面
- 删除无软删追溯需求（P2 锚点即硬删语义）

## 9. E2E 验证步骤

1. 新对话两轮 rag 问答 → 左栏出现会话条目（title=首问、相对时间），DONE 后 ~1s 内刷新可见
2. 「新对话」切走 → 点回该会话 → 消息全量恢复；assistant 回答 `[ref-N]` 徽标内联、溯源面板展开、点徽标/条目弹原文；👍 后刷新会话仍高亮（回显）
3. 续聊追问引用早前上下文 → 模型正确承接（热路径，记忆本在）
4. **回填验证**：`redis-cli`（DB 0）DEL 该会话记忆键模拟 TTL 过期 → 续问「我刚才问了什么」→ 正确复述（回填生效）；service.log 见回填 info 日志
5. tool 模式会话打开 → 消息正常展示（无溯源面板，降级预期）；闲聊轮（无 TRACE）历史无溯源面板
6. 越权：手改 URL/请求他人 sessionId → 404
7. 删除：条目消失；刷新不再出现；当前会话被删 → 回新对话态
8. 收起/展开侧栏布局无破损；流式中条目禁点

## 11. 范围边界（YAGNI）

不做：会话重命名/置顶/搜索；mode 持久化（会话内 rag/tool 混杂，前端模式开关维持用户自选）；历史 TOOL_CALL 卡片恢复（PENDING 审批 TTL 10 分钟早已失效，恢复无意义；assistant 文本照常展示）；分页游标（offset/size 足够）；跨设备会话列表实时同步。
