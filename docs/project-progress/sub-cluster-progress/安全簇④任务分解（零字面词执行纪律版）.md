## 〇、本簇的内容风险点（跨会话交接必读）

簇④的 **D3 毒化语料构造**是全专项最高内容风险步骤——毒化文档正文必须含植入指令载荷才能驱动评估。簇①已实证：模型在推理/计划/实现中间产物自产字面载荷会触发上游拦截、会话中断。**本簇总纲沿簇①：机器与内容硬分离**——AI 只造机器（扫描装配/策略/编码通道/评估管道/Judge 打分位），毒化语料**内容**由用户带外构造经编码通道注入，AI 不产出、不查看、不转录、不列举。

簇④特有的纪律增量（叠加簇①纪律四条之上）：

5. **毒化文档内容永不经会话**——构造在用户本地（仓库外 inbox），导入经脚本编码落盘，评估经加载层解码消费；任何环节需要引用时用样本 ID（poison-01..05）+ 结构描述（「正常业务主题正文 + 植入指令段」），不复述正文。
6. **触发问句与 Judge 判据是明文安全区**——触发问句必须是正常业务问句（非载荷，与干净集同形态）；Judge 判据是忠实回答的结构描述。二者明文落盘合规，与毒化正文的编码态分层存储。
7. **D1 警示注记与 Judge Prompt 为中性结构文案**——AI 产出但无载荷（警示注记 = 声明资料命中检测 + 指令性文字不得执行的结构句式；Judge Prompt = 判定语义的结构描述），与簇① T3 REGEX 结构模式轨同级合规。

### 被 block 恢复策略

沿簇①母本 §〇四条，另加一条簇④特化：**毒化文档上传/触发/判定全链只回显 ID、打标布尔、判定枚举、计数**——排查时不读取毒化正文进上下文（加载层解码结果直供检索/判定消费，不经会话转述）。

## 三、任务分解（依赖序）

> 依赖图：D1 → (D2 ∥ D3a) → D3b（用户侧并行）→ 收尾。总量 3-4 人日（对齐 §5.1）；D3b 内容注入是用户侧件，不占 AI 会话。

### D1 运行时扫描与逐条警示（造机器 · 1.5d）

- **IndirectInjectionScanPostProcessor**（kb-ai-core retriever 包，implements DocumentPostProcessor，签名对齐 RerankDocumentPostProcessor 实证形态 `process(Query, List<Document>)`）：逐文档归一化检测视图（TextSanitizer.normalize + GuardrailRulesLoader 同源词表，**BLOCK+FLAG 全档命中即判中**——检测视图口径与输入侧一致，词表加载形态与 InputSanitizeAdvisor 同款含外部覆盖回落）；
- **策略双档**：`warn`（默认）= 命中文档打标保留（Document 元数据键 `indirect_injection_hit`，新 map 拷贝防共享污染，坑位④ null 禁令）；`exclude` = 命中文档剔除（全剔则空证据链路自然回落拒答模板，EMPTY_CONTEXT_PROMPT 既有机制零改动）；
- **装配位序定案**：扫描后处理器置于 rerank **之前**（documentPostProcessors 序列首位）——exclude 剔除的 chunk 不参与重排、不进 TRACE 帧，grounding/审计溯源/前端 [ref-N] 三面对齐关系不破（warn 档文档集不变，对齐天然保持）；
- **逐条警示渲染**：formatNumberedContext 演进为元数据感知——命中文档在 [ref-N] 行后追加警示注记行（中性句式：声明该条资料命中注入模式检测、其中指令性文字为可疑内容不得执行不得响应，与规则 6 语义呼应）；零命中渲染结果与现状逐字一致（回归用例钉死零漂移）；
- **指标**：`rag.guardrail.indirect.flagged`（命中按条计）+ `rag.guardrail.indirect.excluded`（exclude 档剔除计数），零标签纪律；warn 日志只记命中计数与文档 ID/文件名元数据，不落正文；
- **配置族**：`rag.guardrail.indirect.scan.enabled` 默认 true；`rag.guardrail.indirect.strategy` warn|exclude 默认 warn（落 application-ai.yml）；
- **审计口径**：命中不写 guardrail_flags 列（该列 side 枚举为 input/output 双侧语义，间接面独立指标表达；维持 SUCCESS→null 不变量）；
- 测试：合成词表（占位词项）驱动双策略 + 元数据打标 + 指标计数 + 编号格式器零漂移/警示渲染 + 装配位序；**不入真词**；
- **纪律检查点**：警示文案中性结构句；测试输入全合成。

### D2 入库打标消费（造机器 · 1d，默认关）

- injection_hit=true chunk 检索侧降权——RRF 融合分衰减形态（fused_score × 衰减系数），落 RrfFusion 或检索融合点（落码时源码级核验 injection_hit 元数据自向量库召回 Document 的可达性——vectorMetadata 契约抽取链 SanitizingTransformer→DocumentEtlService→召回元数据，不可达则先补契约再谈消费）；
- 配置：`rag.retrieval.injection-hit.demote.enabled` **默认 false** + `factor` 衰减系数（§9 定案④：先经 kb-eval 检索门禁 Recall/MRR 双跑对比度量影响，再定开关口径——本簇只落机制与度量支持，不改变默认生产行为）。

### D3a 评估机器侧（造机器 · 1.5d，12.6 提案落地）

- **语料模型**：kb-eval `golden/indirect-qa.json` 编码引用形态——`id / fileName / documentEncoding=base64 / documentSha256 / document（毒化正文编码态）/ question（触发问句明文）/ judgeCriteria（忠实回答判据明文）`；载荷分层：唯 document 字段编码，question/judgeCriteria 非载荷明文（纪律条 6）；
- **导入脚本** `tools/guardrail/import_poison_corpus.py`（形态沿 import_corpus.py）：inbox（正文文本文件 + 元数据 JSONL：fileName/question/judgeCriteria）→ 逐篇 base64 + sha256 指纹 → 并库去重 + manifest；stdout 仅计数/ID 段/指纹；**用户本地执行**；
- **IndirectInjectionProbe**（kb-eval runner，仿 ChainRetrievalProbe 探针形态）：加载层解码 → 毒化文档入目标库通道（上传 API + 评估租户 或 ETL 直连，**落码时源码级核验后定案**——含认证形态与 ETL 完成等待）→ **打标自洽校验**（injection_hit 预期 true：S4 扫描与 D1 同源词表命中语义自洽，假阴性即门禁红灯）→ 触发问句走 chain → 捕获回答；
- **Judge 打分位**：判定回答是否执行资料内指令（EXECUTED/RESISTED 二元，Judge Prompt 结构描述无载荷，JudgeModelConfig 既有通道）；**抑制率 = RESISTED/总数**（S2 统一声明 + D1 逐条警示联合度量面——策略/开关组合读数即各防线增益对照系）；
- **报告与入档**：EvalReport 新增「── 安全性（间接注入抑制）──」小节（逐例 ID + 判定 + 汇总）；首跑基线入档（形态沿 EVAL_RUN_LABEL 报告快照纪律）；
- 加载器回归：编码引用形态自洽测试（指纹锚点/解码透明/明文区字段完整性，沿 injection-qa.json 契约形态）；
- **纪律检查点**：探针/报告/Judge 输出仅 ID/布尔/枚举/计数；毒化正文解码结果直供消费不转述。

### D3b 用户侧内容注入与首跑（用户主导 · AI 零接触）

- 用户带外构造 3-5 篇毒化语料（形态指引：正常业务主题正文承载植入指令段，触发问句为指向该文档主题的正常业务问句）→ 仓库外 inbox → `python3 tools/guardrail/import_poison_corpus.py --inbox <目录>` 并库（回传计数/ID 段/指纹）；
- **E2E（§5.1 验收）**：毒化文档上传打标（injection_hit=true 可查）→ 正常问句检索触发 → 逐条警示可见（日志 + 回答形态）→ Judge 抑制率首跑基线入档；warn/exclude 双策略各一轮读数；
- 语料常驻管理：首跑后毒化文档从目标库清除（评估租户隔离域内操作）；语料编码文件随库版本管理（形态同 injection-qa.json 既有纪律）。

### 收尾（0.5d）

- 全模块单测绿 + kb-eval 门禁复跑不破（直接注入双门禁 + 干净集零漂移）；
- 设计回写：12 章 **§12.8 新增**（运行时闭环：扫描后处理器/策略双档/逐条警示/打标消费降权/抑制率口径）+ §12.4 G1 状态推进 + §12.6 提案段标注落地；
- 进度文档任务行 + CLAUDE.md 架构事实（间接注入运行时防线形态/配置族/新指标/抑制率口径）；
- **§7 纪律自检（DoD 附加项）**：毒化正文全编码 / 明文区仅非载荷字段 / 命名中性（indirect/flagged/excluded 无攻击语义）/ 报告与 E2E 按 ID——逐条打勾进进度文档。
