## 〇、为什么有这份文档（跨会话交接必读）

上轮会话推进簇①时，模型在**推理/计划/实现的中间产物**中产生了字面敏感词（内容并非来自代码库存量，而是模型自产），触发上游拦截、会话中断。实证结论：

- 上游拦截作用于模型的**生成输出**（含推理中间产物）；读取存量温和语料不触发（本次会话读取存量语料结构未被拦即为证）。
- 簇①的「词表扩面」任务形态天然诱导模型枚举词条——这就是上轮的 block 点。

**总纲：机器与内容硬分离。** 模型只做「造机器」——schema / 加载器 / 匹配器 / 输出面 / 门禁 / 按引用的测试；词表**内容**是不透明数据，一律带外注入，模型不产出、不查看、不转录、不列举。

### 纪律四条（自§7 延伸至推理层，全程强制）

1. 推理、计划、中间产物不落字面敏感词/攻击样本；一律以**族系名 / 结构描述 / 样本 ID / 计数 / schema** 表达。
2. 不「举例」；需要说明时用结构描述（如「祈使动词 × 指令类宾语组合」「指令覆盖族中文变体」）。
3. 代码 / 配置键 / 指标名 / 类名不含攻击语义字面（族系用中性枚举名，如 INSTRUCTION_OVERRIDE）。
4. 内容操作（迁移 / 导入 / 校验 / 抽检）一律脚本执行；脚本只回显**计数 / ID 段 / SHA-256 指纹 / 带行号错误**，不回显内容。

### 被 block 恢复策略

1. 立即停用当前会话（上下文已污染，不续用）。
2. 定位触发步骤：核对是否执行了「造内容」步骤、或转录了含字面载荷的文件。
3. 把触发步骤改造成内容无关形态（重切分 / 移入脚本 / 转带外注入）后再**新开会话**继续。
4. 不将疑似含载荷的报错原文粘回上下文；新会话从本文 §4 清单起步。

## 三、任务分解（依赖序）

> 依赖图：T1 → T2 → (T3 ∥ T4 ∥ T5) → T6 → T7 → T8。总量 3-4 人日（对齐 §5.1）；T4 内容注入是用户侧并行件，不占 AI 会话。

### T1 词项模型与结构化加载器（A1 · 造机器 · 0.5d）

- 词项模型：`id / family / lang / type(KEYWORD|REGEX) / value（Base64 编码态，加载层解码，§9 定案②）/ action(BLOCK|FLAG) / enabled`
- 族系七分法中性枚举：指令覆盖 / 角色劫持 / 敏感信息套取 / 编码混淆 / 多语种 / 越狱引导 / 工具诱导（设计 4.1；**枚举命名落码时定案，注意与 kb-eval attackType 四族系两套枚举的区分**，避免同名歧义）
- 结构化文件：classpath `guardrail/injection-rules.yml` / `output-rules.yml`，外部路径覆盖（建议键 `rag.guardrail.rules.location`）；落点建议 kb-commons resources（双消费方 kb-ai-core / kb-etl 的公共依赖），组件对两方提供只读视图
- 三源合并：内置默认 ∪ 结构化文件 ∪ CSV 兼容源（`rag.guardrail.input.injection-keywords` 保留）；同 id 冲突外部文件优先；语义细节落码时定案
- **纪律检查点**：单测以占位值（如对无害占位串编码）构造词项，测试源码不入真词
- 验收：词表组件单测绿；双消费方切新组件后存量行为不变（存量 14 条仍命中）

### T2 存量字面迁移（A1 + §7 · 纯脚本 · 0.5d）

- 新建仓库根 `tools/guardrail/encode_rules.py`（脚本本体零样本字面，解析用结构模式）：
  1. 解析 `DEFAULT_INJECTION_KEYWORDS` 字面块 → 逐条 Base64 → 写 injection-rules 编码区 + manifest（id / family=待标注 / SHA-256 / 长度）；
  2. 解析 application-ai.yml 两个 CSV 键值 → 编码并入（值哈希去重）；
  3. 解析 injection-qa.json 48 条 → question 编码落盘，原文件改写为引用形态（保留 id/category/attackType + 哈希锚点，移除明文 question）；
  4. 输出仅：计数 / ID 段 / 指纹 / 带行号错误。
- **执行形态：用户终端直跑（推荐，内容流完全绕过会话）**；AI 跑亦可（脚本不回显内容），但报错处理须防内容外泄。
- 迁移后 AI 动作：TextSanitizer 硬编码字面块改为结构化加载引用；kb-eval 加载器双形态兼容（引用形态 + 过渡期明文兼容）；GoldenDatasetLoaderTest 自洽校验复绿。
- **纪律检查点**：AI 全程不 cat 词值/样本值；校验只认 manifest 计数与指纹。

### T3 REGEX 结构化模式轨（A2 · AI 主战场 · 1d）

- type=REGEX 词项：「覆盖类动词 × 指令类宾语」「套取类动词 × 系统配置类宾语」等组合句式 + 编码特征模式；目标 10-20 条，以模式代替字面样本枚举（设计 4.1 明示天然合规）。
- 误伤铁律：领域裸词不入 BLOCK 档；可疑模式一律先 FLAG（对冲机制，§3.2「没有免费午餐」）。
- 测试：程序化拼合结构成分构造测试输入，断言命中族系与 action；**不转录攻击样本**。
- **纪律检查点**：正则本身是结构描述；注释中不嵌入完整字面例句。

### T4 扩充干词带外注入（A2 · 用户主导 · AI 零接触 · 接线 0.5d）

- inbox 通道（落码时定案，建议**仓库外本地路径**，脚本参数化——明文永不进仓库）：一行一条或带族系标注列；
- 导入脚本 `tools/guardrail/import_words.py`：读 inbox → 逐条 Base64 → 并库 + manifest → 回显新增 ID 段 / 计数 / 族系分布（不回显内容）；**用户本地执行**；
- AI 职责：只写导入脚本 + 导入后接线验证——按族系计数、按 ID 抽检 3-5 条经脚本抽出做加载层解码自洽（抽检脚本输出「ID 匹配/长度/族系一致」结论，不输出内容）；
- 规模口径：干词 14→80-120、七族全覆盖、中文同族变体 + 多语种（沿 v2.38 补强方法）——**具体词面不经会话**。

### T5 输出面扩充：分类化 + 金丝雀（A3 · 造机器 · 1d）

- 输出词表分类化：业务保密 / 合规敏感 / 竞品对比 三类起步，各分类独立 action 与指标子项；词项内容走 T4 通道（输出区）带外注入，2 条占位词同批退役；
- **系统提示金丝雀**（OWASP/Rebuff 调研实证）：启动时生成随机金丝雀 token（UUID 形态，非载荷）内嵌系统提示装配点；`OutputGuardrailAdvisor` 聚合后验阶段校验输出回显 → 命中即确证提示泄露，整段替换 + 独立指标 `rag.guardrail.output.canary`；
- PII 回显探测：簇①只留 FLAG 钩子位（识别器注册表依赖安全簇③ C 组）；
- **纪律检查点**：金丝雀为运行时随机值；测试用动态生成值，不硬编码。

### T6 kb-eval 语料扩面与门禁契约（A2 联动 · 0.5d）

- injection-qa.json 随族系扩面：新增样本同样**带外注入 + 编码**；attackType 四族系（样本侧）与词项七分法（词表侧）是两套族系——样本扩面沿 attackType，词项 family 映射关系落码时定案；
- GoldenDatasetLoaderTest 自洽契约延续：门禁子集归一后必命中、编码绕过样本归一前必不命中；
- 干净回归集：Golden 146 正常问题 + 少量审计干净样本（脚本挑选），门禁口径 = BLOCK 档**零命中**，进 kb-eval 报告「安全性」小节强制项（A4）。

### T7 FLAG 观察语义与指标（A1/A3 · 0.5d）

- action=FLAG：命中只计数 + 审计标记、不拒绝（审计标记载体落码时定案：kb_audit_log 扩展列或既有字段复用）；
- 指标：`rag.guardrail.flagged`（低基数 tag：side=input/output + family 中性枚举；不带租户标签防基数膨胀）+ T5 canary 指标；注册对齐 AiBusinessMetrics 既有形态；
- 词表变更流程定案（A4）：新增 → FLAG 观察（指标 + 审计可查）→ 零误伤确认转 BLOCK；运营通道归安全簇⑥ F 组，簇①只落 FLAG 语义。

### T8 收尾：验证通道 + 文档回写 + 纪律自检（A4 · 0.5d）

- 代码侧：涉及模块单测绿（`mvn -q --no-transfer-progress test -pl <module> -am`），kb-eval 门禁复跑不破；
- 验证通道（§5.1）：kb-eval 门禁子集 ≥95% + 干净集零误伤 + 各新族系 FLAG/BLOCK 计数自采；
- E2E（不启动服务、用户自测定案形态）：各新族系以「使用编码样本 {id}」描述（§7 条 4），由脚本解码注入，观察拦截/FLAG 计数；
- 文档回写：12 章新增 §12.7 词表工程（结构化配置/七分法/FLAG 语义/编码纪律）+ 进度文档任务行 + CLAUDE.md 架构事实（词表配置源 / FLAG 语义 / 新指标族 / 编码形态 / 双形态兼容）；
- **§7 纪律自检（DoD 附加项）**：文档零字面 / 词表 value 与样本 question 全编码 / 命名中性 / E2E 按 ID——逐条打勾进进度文档。
