### 1.2 schema.sql 应用方式 — init script + ddl-auto=validate

**定稿方案**：PostgreSQLContainer.withInitScript() + PgVectorStore initializeSchema=true

| 阶段 | 负责组件 | 内容 |
|---|---|---|
| 容器启动 | `init-test-schema.sql`（init script，以 postgres 超级用户执行） | `CREATE EXTENSION IF NOT EXISTS vector` + 8 张业务表 DDL（从 schema.sql 摘录，去掉 kb_embeddings 与 CREATE INDEX hnsw） |
| Bean 初始化 | `PgVectorStore.Builder.initializeSchema(true)` | 以应用用户创建 `kb_embeddings` 表 + HNSW 索引（pgvector Java driver 自带此能力，源码核验） |
| 上下文就绪 | Hibernate `ddl-auto=validate` | 校验 8 张业务表 Entity ↔ DDL 一致性 |

**init-test-schema.sql 骨架**（`kb-eval/src/test/resources/it/init-test-schema.sql`）：

```sql
-- 超级用户执行：pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 8 张业务表 DDL（直接从 schema.sql 复制，去掉 kb_embeddings 部分）
CREATE TABLE IF NOT EXISTS kb_document ( ... );
CREATE TABLE IF NOT EXISTS kb_section ( ... );
CREATE TABLE IF NOT EXISTS kb_chunk ( ... );
CREATE TABLE IF NOT EXISTS kb_session ( ... );
CREATE TABLE IF NOT EXISTS kb_message ( ... );
CREATE TABLE IF NOT EXISTS kb_audit_log ( ... );
CREATE TABLE IF NOT EXISTS kb_feedback ( ... );
CREATE TABLE IF NOT EXISTS kb_prompt_template ( ... );

-- 索引（与 schema.sql 保持一致）
CREATE INDEX IF NOT EXISTS idx_tenant_status ON kb_document (tenant_id, status);
-- ... 其余索引
```

**理由**：init script 在容器首次创建时执行一次（Testcontainers 保证），避免了 ResourceDatabasePopulator 的 @BeforeAll 重复执行问题；CREATE EXTENSION 需 superuser 而 PostgreSQLContainer 默认以 postgres 用户运行 init script；PgVectorStore 的 initializeSchema 处理向量表（应用用户权限即可）。

## 二、模型桩设计

### 2.1 ChatModel 桩替换策略

**定稿方案**：exclude deepseek + openai 自动装配 → 同名 Bean 注册 stub

**排除的自动装配类**：
- `org.springframework.ai.autoconfigure.chat.model.ChatModelAutoConfiguration`（如有）
- `org.springframework.ai.model.deepseek.autoconfigure.DeepSeekChatModelAutoConfiguration`
- `org.springframework.ai.model.openai.autoconfigure.OpenAiChatModelAutoConfiguration`
- `org.springframework.ai.model.openai.autoconfigure.OpenAiEmbeddingModelAutoConfiguration`
- `org.springframework.ai.autoconfigure.chat.client.ChatClientAutoConfiguration`（避免自动装配 ChatClient.Builder 取不到 @Primary 的边界问题）

**排除方式**：测试启动类 `@SpringBootApplication(exclude = {...})`。

**理由（vs @MockitoBean/哑 key）**：
1. **@MockitoBean 不可行**：`smartRoutingChatModel` 经 `@Qualifier("deepSeekChatModel")` 硬注入，MockitoBean 替换的是类型匹配而非 Bean 名，Qualifier 路由会失效。且 SmartRoutingConfig 在 @Bean 方法内直接读取 deepSeekChatModel 参数，Mockito 代理不保证 @Qualifier 语义。
2. **哑 key + 真实自动装配**：deepseek starter 的 @ConditionalOnMissingBean 不检查 key 是否有效，装配成功但启动后任何调用都打真实 API——零隔离。
3. **exclude + 同名 Bean**：干净物理隔离，`@Qualifier("deepSeekChatModel")` 解析到 stub Bean，SmartRoutingConfig 正常装配（fallback 为 null 走单模型形态），与生产链路字节码路径完全一致。

### 2.2 StubChatModel 实现

```java
// kb-eval/src/test/java/com/enterprise/kb/eval/it/stub/StubChatModel.java
public class StubChatModel implements ChatModel {

    // 可编程：主回答文本
    private volatile String defaultAnswer = "这是桩模型的默认回答。";
    // 可编程：Usage token 数
    private volatile int promptTokens = 100;
    private volatile int completionTokens = 50;
    // 可编程：按 prompt 内容路由回答（用于 L2 分类器返回 IntentResult JSON）
    private volatile Function<String, String> responseRouter = null;
    // 流式分块大小
    private volatile int streamChunkSize = 10;

    public void setDefaultAnswer(String answer) { this.defaultAnswer = answer; }
    public void setUsage(int prompt, int completion) {
        this.promptTokens = prompt;
        this.completionTokens = completion;
    }
    public void setResponseRouter(Function<String, String> router) { this.responseRouter = router; }

    @Override
    public ChatResponse call(Prompt prompt) {
        String userText = prompt.getUserMessage().getText();
        String answer = (responseRouter != null) ? responseRouter.apply(userText) : defaultAnswer;
        return buildResponse(answer);
    }

    @Override
    public Flux<ChatResponse> stream(Prompt prompt) {
        String userText = prompt.getUserMessage().getText();
        String answer = (responseRouter != null) ? responseRouter.apply(userText) : defaultAnswer;
        // 分块：每 chunk streamChunkSize 字符，末块含 Usage
        List<String> chunks = splitIntoChunks(answer, streamChunkSize);
        return Flux.fromIterable(chunks)
            .map((chunk) -> {
                boolean isLast = chunk.equals(chunks.get(chunks.size() - 1));
                return buildResponse(chunk, isLast);
            });
    }

    private ChatResponse buildResponse(String text) { return buildResponse(text, true); }

    private ChatResponse buildResponse(String text, boolean includeUsage) {
        DefaultUsage usage = includeUsage
            ? new DefaultUsage((long) promptTokens, (long) completionTokens)
            : new DefaultUsage(0L, 0L);
        return new ChatResponse(
            List.of(new Generation(new AssistantMessage(text))),
            new ChatResponseMetadata.Builder()
                .usage(usage)
                .model("stub-model")
                .build()
        );
    }

    private static List<String> splitIntoChunks(String text, int chunkSize) {
        if (text == null || text.isEmpty()) return List.of("");
        List<String> chunks = new ArrayList<>();
        for (int i = 0; i < text.length(); i += chunkSize) {
            chunks.add(text.substring(i, Math.min(i + chunkSize, text.length())));
        }
        return chunks;
    }
}
```

> **2.0 GA 形态注意**：`ChatResponse` 构造器接受 `ChatResponseMetadata`（非 `Map`），`Usage` 接口实现类为 `DefaultUsage`（`spring-ai-core` 包），需源码核验确切构造器签名。实现期若 API 微调以实际为准。

### 2.3 StubEmbeddingModel 实现

```java
// kb-eval/src/test/java/com/enterprise/kb/eval/it/stub/StubEmbeddingModel.java
public class StubEmbeddingModel implements EmbeddingModel {

    private static final int DIMENSIONS = 1024;

    @Override
    public float[] embed(String text) {
        // 确定性哈希：同文本必同向量
        byte[] hash = MessageDigest.getInstance("SHA-256").digest(text.getBytes(StandardCharsets.UTF_8));
        float[] embedding = new float[DIMENSIONS];
        for (int i = 0; i < DIMENSIONS; i++) {
            embedding[i] = ((hash[i % hash.length] & 0xFF) - 128) / 128.0f;
        }
        // L2 归一化（余弦距离可比）
        float norm = (float) Math.sqrt(Arrays.stream(embedding).mapToDouble(v -> v * v).sum());
        if (norm > 0) for (int i = 0; i < DIMENSIONS; i++) embedding[i] /= norm;
        return embedding;
    }

    @Override
    public Embedding embed(Document document) {
        return new Embedding(embed(document.getText()), 0);
    }

    @Override
    public List<Embedding> embed(List<Document> documents) {
        return documents.stream().map(this::embed).toList();
    }

    @Override
    public int dimensions() { return DIMENSIONS; }
}
```

**跨租户隔离用例的区分机制**：向量本身不需要租户感知（同文本同向量），隔离由 PgVectorStore 的 `FilterExpression`（`tenant_id == X AND is_deleted == false`）在检索时实现。StubEmbeddingModel 只需保证相同内容落入相同向量位置，filter 表达式负责返回正确租户的结果。

```java
// kb-eval/src/test/java/com/enterprise/kb/eval/it/TestEvalApplication.java
@SpringBootApplication(
    scanBasePackages = "com.enterprise.kb",

        // 排除真实模型自动装配（由 StubModelConfig 替代）

        McpClientAutoConfiguration.class

        type = FilterType.ASSIGNABLE_TYPE,
        classes = {
            EvalRunner.class,         // 避免 ApplicationReadyEvent 触发全量评估
            AnnotationRunner.class,   // 避免 ApplicationRunner 执行探针查询
            JudgeModelConfig.class    // judge api-key 空 → 启动即抛异常
        }
    )
)
@EntityScan("com.enterprise.kb.domain.model")
@EnableJpaRepositories("com.enterprise.kb.domain.repository")
@EnableConfigurationProperties(EvalProperties.class)
public class TestEvalApplication {
    // 空体：仅作为 @SpringBootTest(classes=...) 的启动元数据
}
```

**EvalRunner 隔离方案定稿：测试专属启动类**

| 维度 | 分析 |
|---|---|
| **为何不用属性门** | EvalRunner.runOnStartup 的门控逻辑为 `!ci && args.containsOption("eval.annotate-query")` 提前返回 + `judge key 空` warn+return。但后者在 judge key 为空时仅 warn 返回——而 JudgeModelConfig 在 Bean 创建阶段就抛异常，早于 EvalRunner 执行。排除 JudgeModelConfig 后 EvalRunner 的构造注入 `@Qualifier("judgeChatClient") ChatClient` 会报 NoSuchBeanDefinition。故仅靠属性无法解决，必须排除 EvalRunner 本身。 |
| **对其他 @Component 的影响** | excludeFilters 只排除 3 个类（EvalRunner / AnnotationRunner / JudgeModelConfig）。kb-eval 包下的其余组件（GoldenDatasetLoader、RetrievalMetrics 等 POJO/工具类）不受影响。kb-ai-core 包下所有 Advisor/Config/Service 全量扫描。 |
| **EvalProperties 注册** | TestEvalApplication 显式 @EnableConfigurationProperties(EvalProperties.class)，保留配置绑定。 |
| **排除 JudgeModelConfig 的连带** | judgeChatClient Bean 不再存在。EvalRunner（唯一消费者）已排除，无引用链断裂。 |

### 6.2 Docker 不可用失败语义

**快失败策略**：Testcontainers 自身在 Docker daemon 不可达时抛 `IllegalStateException("Could not find a valid Docker environment")`——此异常在容器 `start()` 时触发（即基类静态块），发生在任何 @Test 执行前。

增强措施：在 `AbstractAdvisorChainIT` 的静态块中 catch 并打印清晰提示：

```java
static {
    try {
        pg.start();
        redis.start();
    } catch (Exception e) {
        throw new ExceptionInInitializerError(
            "╔══════════════════════════════════════════════════╗\n" +
            "║  Docker 不可用，集成测试无法执行。              ║\n" +
            "║  请启动 Docker Desktop 后重试。                  ║\n" +
            "║  若 CI 环境无 Docker，请在 maven 命令中加       ║\n" +
            "║  -DskipITs 跳过集成测试。                       ║\n" +
            "╚══════════════════════════════════════════════════╝\n" +
            "Root cause: " + e.getMessage());
    }
}
```

### 8.1 Boot 4.1 / Spring AI 2.0 形态坑

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| ① | `@ConditionalOnMissingBean` 让位：exclude 自动装配后，stub Bean 是否仍触发条件判定 | 若 Spring AI 自动装配类在 exclude 列表不全时残留，stub Bean 可能被条件跳过 | 明确排除所有相关 AutoConfiguration 类（DeepSeek/OpenAI/ChatClient/MCP），实现期逐一核验；CI 跑一次空跑确认 Bean 图谱 |
